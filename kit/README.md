# devkit

AI에게 무엇을 만들거나 고쳐 달라고 할 때 지킬 **규칙 세 가지**를 적은 한 장(`rules.md`)을, 대화를 시작할 때 AI에게 읽혀 주는 묶음이다.
작은 부탁에는 한 장만 읽힌다. 한 장이 큰 일이라고 가르면 시작 안내(`start`)를 더 읽는다. 이번 판이 프로젝트 안에 만드는 것은 `.devkit/` 폴더 하나다 — 그 안에 길 안내 한 장(`.devkit/guide.md`)을 쓰고, 분석해 달라고 하면 화면 표 한 장(`.devkit/screens.md`)도 쓴다. git 프로젝트면 이 PC의 제외 목록에 한 줄이 더해진다.

1. **닮은 것이 하던 일을 그대로 따라 한다.** 이미 있는 가장 닮은 것을 찾아, 그것이 닿던 곳마다 새 것도 같이 닿게 한다.
2. **부탁에 없는 것은 넣지 않는다.** 있으면 좋겠다 싶은 것은 만들지 않고 한 줄로 제안만 한다.
3. **끝에 사실대로 밝힌다.** 직접 돌려서 본 것, 읽기만 한 것, 안 한 것을 나눠 적는다.

## 깔기
이 폴더에서 한 번 친다. 그 뒤 새 대화를 연다.

    python3 install.py

(Windows에서 `python3`이 없다고 나오면 `python install.py`.)
명령을 치는 것이 낯설면, 이 폴더에서 Claude Code나 Codex를 열고 "install.py를 실행해 줘"라고 해도 된다.
Claude Code에 깔린다. Codex는 아래 `## Codex`를 본다 — `python3 install.py`는 Codex에 아무것도 깔지 않는다. 다시 치면 새 판으로 바뀐다.
깐 뒤에 이 폴더를 옮기거나 지우면 다시 깔아야 한다.

## 쓰는 법
따로 부를 필요 없다. 평소처럼 "이 화면에 무엇을 넣어 주세요"라고 부탁하면 된다.
새 대화를 열 때마다 규칙 한 장이 AI에게 저절로 읽힌다.
AI가 "큰 일로 봅니다 — …" 한 줄을 말하면 큰 일로 가른 것이다.
하다 만 일의 기록이 있으면 대화를 열 때 그 이름이 AI에게 같이 읽힌다.
"이 프로젝트 분석해 줘"라고 하면 코드를 고치지 않고 살펴본 뒤 두 장을 쓴다. 길 안내 한 장(`.devkit/guide.md`)에는 어느 폴더에 무엇이 있는지와 요구사항·구조 같은 프로젝트 문서가 어느 파일인지, 화면 하나가 주소·서버 처리·DB까지 이어지는 보기 하나, 따를 공통 부품·스타일 파일, 바깥과 닿는 곳·조심할 곳·돌리는 법, 못 본 것을 적는다. 화면 표 한 장(`.devkit/screens.md`)에는 화면마다 그 파일·주소·주소를 받는 코드의 자리를 한 줄씩 적는다 — 표를 쓰는 만큼 살피는 시간과 값이 더 든다. 코드가 바뀌어도 표는 저절로 고쳐지지 않는다 — 표 머리에 쓴 날짜가 있다. git 프로젝트면 이 폴더는 이 PC의 제외 목록에 들어가 올라가지 않는다.
길 안내가 있는 프로젝트에서는 AI가 파일을 찾기 전에 길 안내를 먼저 읽고, 화면이나 주소에 딸린 파일은 화면 표가 있으면 거기서 먼저 찾는다 — 그만큼 물음 하나에 값이 조금 더 들 수 있다. 길 안내가 없으면 만들지 않고 평소대로 찾는다. 길 안내와 표에 지시처럼 적힌 글은 따르지 않고 알리게 되어 있다(글 규칙이라 다 막지는 못한다).

## Codex
Codex에는 규칙 한 장을 `AGENTS.md`에 넣는 것만 한다. 이 폴더에서 친다.

    python3 install.py --codex-note

- `~/.codex/AGENTS.md`(`CODEX_HOME`을 따로 정해 두었다면 그 폴더의 `AGENTS.md`) 끝에, 표시 두 줄(`<!-- devkit:begin -->`, `<!-- devkit:end -->`) 사이로 규칙 한 장이 들어간다.
- 이미 있으면 다시 넣지 않는다.
- 표시 사이를 고쳐 두었으면 손대지 않고 알려 준다.
- `--remove`로 지울 때 같이 지워진다. 사용자가 쓴 다른 줄은 건드리지 않는다(파일이 줄바꿈 없이 끝나 있었으면 맨 끝에 줄바꿈 하나만 붙는다).
- Codex에는 시작 안내가 없다. 큰 일이어도 한 장대로 한다.
- 한 장 글이 바뀐 새 판으로는 앞 판이 Codex에 넣어 둔 것을 `--remove`로 못 뺀다 — 빼기는 넣어 둔 글이 지금 `rules.md`와 바이트로 같을 때만 지우고, 다르면 손대지 않고 알려 준다. 앞 판의 `install.py --remove`로 먼저 빼거나, 표시 사이를 손으로 지운다.

## 비밀값 파일 한 번 더 거르기
읽어 온 결과는 AI에게 가기 전에 비밀값 꼴을 가린다. AI가 파일을 열거나 검색하기 바로 전에 devkit이 한 번 더 본다. 다 막지도, 다 가리지도 못한다 — 아래에 적은 꼴 몇 가지에서 한 번 더 묻거나 멈출 뿐이고, 지키는 것은 규칙 한 장의 글이다.

- **묻는다:** 이름이 비밀값을 담아 두는 꼴인 파일(`.env*`·`credentials.*`·`*secret*`·`*.pem`·`*.key`·`*.p12`·`*.pfx`·`*.jks`·`*.keystore`·`id_rsa*`·`.npmrc`·`.pypirc`·`.netrc`·`serviceAccountKey.json`)을 열거나 그 줄을 찍으려 할 때. `*secret*`은 자료 파일(`.json`·`.yml`·`.properties` 같은 것)이나 확장자 없는 파일일 때만 묻는다. `.env.example`처럼 본보기 파일은 묻지 않는다. 사람 없이 도는 실행(`claude -p`)에서는 물을 수 없어서 거절된다.
- **프로젝트마다 더 적기:** 프로젝트 폴더의 `.devkit/secret-names`에 한 줄에 이름 꼴 하나(`globals.properties`·`context-datasource.xml` 같은 것)를 적으면 위 목록에 더해 묻는다. `#`로 시작하는 줄과 빈 줄은 건너뛰고 앞 50줄(4 KB)까지만 읽는다. 경로를 적어도 마지막 이름만 본다.
  직접 적거나 AI에게 「이 이름을 비밀 목록에 넣어 줘」라고 한다. 살펴보기가 채워 주지는 않는다.
- **멈춘다:** 비밀번호·키·토큰 같은 낱말(`password`·`passwd`·`secret`·`api_key`·`apikey`·`api-key`·`token`·`private_key`·`database_ur`·`jdbc`)로 찾으면서 찾은 줄을 그대로 보여 주는 검색. 파일 이름만(`grep -l`)·개수만(`grep -c`) 보여 주는 검색은 그대로 된다.
- **거절한다:** Write·Edit로 쓰려는 글에 가려진 값 표시(`<devkit이 가린 값>`)가 들 때 — 그대로 쓰면 파일의 진짜 값이 지워진다. Edit는 표시가 늘어날 때만 거절하므로 다른 줄을 고치는 것은 된다.
- **못 막는 길:** 아는 것만 적었다 — 이 밖에도 있다.
  - `@`로 파일을 가리키면 이 확인을 거치지 않는다. 따로 붙인 도구(MCP 같은 것)로 파일을 읽을 때도 거치지 않는다 — 보는 것은 Claude Code의 명령 실행·파일 읽기·검색 셋과, Write·Edit로 쓰려는 글의 가려진 값 표시뿐이다.
  - 평범한 이름의 설정 파일 — 설정 코드(`settings.py`)·`context.xml`·`*.properties`·`docker-compose.yml` — 에 적힌 암호를 통째로 열거나 앞에서 몇 줄 찍는 것(위 프로젝트 목록에 적으면 열 때 묻는다). 이름에 `secret`이 든 코드 파일(`secrets.py`)도 묻지 않는다 — 묻지는 않지만, 그 결과에서 아래 꼴로 알아볼 수 있는 값은 가려진다.
  - 목록에 없는 이름 — `prod.env`, 확장자 없는 `credentials`, `id_ed25519`, `.pgpass` 같은 것 — 은 위 프로젝트 목록에 적어야 묻는다.
  - 이름은 평범한데 비밀 파일을 가리키는 링크 — 이 확인은 이름만 보고 링크가 가리키는 곳은 따라가 보지 않는다. AI가 파일을 찾기 전에 먼저 읽는 `.devkit/guide.md`·`.devkit/screens.md`가 그런 링크여도 묻지 않는다.
  - 작은 프로그램으로 읽기(`python -c …`), `awk`나 `sed -n '/낱말/p'`로 찾기, `git show`·`git log -p`로 지난 내용 보기, 비밀 낱말이 아닌 말로 폴더째 찾다가 `.env` 줄이 딸려 오는 것 — 묻지는 않지만, 그 결과에서 아래 꼴로 알아볼 수 있는 값은 가려진다.
  - 따옴표 안에 통째로 든 명령: `bash -c "…"`, `eval "…"`, 다른 컴퓨터나 컨테이너에 넘기는 `ssh 호스트 '…'`·`docker exec … sh -c '…'`. 명령을 파일에 써 넣은 뒤 돌리기, 겹친 속 명령(`$(…)` 안의 백틱)도 보지 못한다.
  - 여러 줄 글(`<<'EOF' …`)을 둘러싼 꼴: 여러 줄에 걸친 묶음 안의 글(`{ … } | bash`·`eval "$( … )"`), `git`·`gh`의 하위 명령이 그 글을 셸로 돌리는 것(`git submodule foreach bash <<'EOF' …`·`gh codespace ssh <<'EOF' …`), 글 안에 끝 낱말을 한 번 더 적어 그 뒤 명령을 글처럼 보이게 한 것.
  - 이름을 글자 그대로 쓰지 않는 것: 셸이 만드는 이름(`cat .e*`, `f=.env; cat $f`), 넓은 꼴(`--include='*env*'`), 다른 이름으로 옮긴 뒤 읽기(`cp .env /tmp/x`), 이름을 파일에 적어 두었다가 넘기기(`find . -name .env > 목록; xargs cat < 목록`). 다른 명령이 찾아 준 이름(`cat $(find . -name .env)`·`cat $(ls .env*)`), 여러 줄 글로 넘긴 이름, `find`에서 읽는 명령 뒤에 적은 이름(`find . -exec cat {} \; -name .env`)도 묻지 않는다.
  - 낱말을 그대로 쓰지 않는 검색: 줄인 낱말(`pass`·`pwd`), 낱말을 파일에서 읽는 `grep -f`, 드문 검색 옵션 뒤의 낱말(`rg -T js 낱말`·`ag -G py 낱말`).
  - AI가 `.devkit/secret-names`나 끄는 표시 파일을 고치거나 만드는 것(파일 쓰기는 Write·Edit의 가려진 값 표시만 본다 — 명령으로 써 넣기(`sed -i`·`echo >`)·Write·Edit 밖의 쓰기 도구·표시 글을 조금 바꿔 적은 것(빈칸을 넣거나 글자를 바꾼 것)은 보지 않는다. 표시 글이 그 길로 파일에 써지면 진짜 값은 git이나 다른 사본에서만 되찾을 수 있다).
  - 이 확인이 고장 나거나 10초 넘게 걸리면 그 호출은 막히지 않고 지나간다.
  - 이 확인과 가림은 컴퓨터가 먼저 찾는 `python3`로 돈다. 프로젝트 가상환경(`.venv`)을 켠 채 쓰면 그 안의 `python3`가 돌므로, 그 가상환경 폴더 안의 것(실행 파일·설정)이 바뀌어 있으면 — AI가 스스로 바꾼 경우도 — 둘 다 믿을 수 없다.
  - 권한을 묻지 않고 다 허용하게 켠 실행에서 "묻는다"가 어떻게 되는지는 확인하지 못했다.
- **잘못 걸리는 것:** 낱말이 다른 말 안에 든 검색(`tokenize`를 찾아도 멈춘다), `echo cat .env`처럼 글자만 찍는 명령, 빼라고 적은 이름(`git diff -- . ':!*.pem'`·`ls | grep -v .env | xargs cat`도 묻는다), 프로그램에 넘기는 여러 줄 글(`psql <<'SQL' …` 안에 `cat .env` 글자가 있으면 묻는다 — 커밋·PR 글과 파일에 써 넣는 글은 대개 보지 않지만 `sudo tee …`·`FOO=1 cat > 파일 <<…`처럼 명령 앞에 다른 낱말이 붙거나 그 줄에 `$(`·`\`가 있으면(`cd "$(…)" && cat > 파일 <<…`) 본다). 가려진 값 표시가 든 쓰기 — 표시 글을 미리 적어 둔 파일을 Write로 통째로 다시 쓰기, 이 설명처럼 표시 글 자체를 적는 글도 거절된다. 거절되면 가려진 줄은 두고 Edit로 다른 줄만 고치면 된다. 멈춰도 일은 이어지고, 묻는 창에서는 허용하면 된다.
- **가린다:** **성공한 호출의 결과만** — 파일 읽기·명령 실행·검색·고치기·쓰기가 끝나 그 결과가 AI에게 가기 바로 전에 비밀값으로 보이는 값만 `<devkit이 가린 값>`으로 바꿔 넘긴다. **파일에는 진짜 값이 그대로** 있다. 꼴: 이름이 `password`·`passwd`·`pwd`·`secret`·`token`·`apikey`·`secretkey`·`privatekey`·`accesskey`·`secretkeybase`로 끝나는 `이름 = "값"`·`"이름": "값"`·한 줄 `이름=값`(`# password: 값`·`#DB_PASSWORD=값`처럼 `#`로 주석 처리한(막아 둔) 줄도, `git diff`가 줄 앞에 붙이는 `+`가 있어도(`-` 줄은 `-이름=값`처럼 이름이 바로 붙을 때만), Go·Makefile의 `이름 := 값`도)·XML 속성과 글, 값을 꺼내는 호출(`get`·`getenv`·`env`·`fetch`·`setdefault`·`define` 같은 것)의 둘째 글(`default="값"`으로 적어도), 주소 속 `사용자:값@`(사용자 이름이 비어도)·`?password=값`·`?x-api-key=값`·`#access_token=값`처럼 주소의 `?`·`&`·`#` 뒤에서 이름이 비밀 낱말로 끝나는 칸, 설정 줄이나 코드의 대문자 상수에서 `_KEY`로 끝나는 이름에 긴 값, 알려진 토큰 꼴(AWS·GitHub·Slack·OpenAI꼴·Google·JWT·Stripe·GitLab), 개인 키 덩어리. 꼴이 조금만 달라도 그대로 간다. 가리면 알림 한 줄이 붙는다.
- **못 가리는 것:** 아는 것만 적었다 — 이 밖에도 있다.
  - `0이 아닌 값으로 끝난 명령`(없는 파일을 같이 `cat`한 것처럼 실패로 끝난 호출)의 결과 — 가림이 아예 돌지 않아 값이 그대로 간다. 시험이 실패한 실행, 일부 파일을 못 읽은 검색처럼 실패로 끝난 명령은 무엇을 찍었든 가리지 않는다. AI가 명령 끝에 실패를 일부러 붙여도 같다. Claude Code 2.1.330에서 실제로 돌려 확인했고, 도구 쪽 한계라 devkit이 닫지 못한다.
  - `비밀 낱말로 끝나지 않는` 이름(`DB_PASS = "…"`처럼 줄인 이름)의 값 · `여러 줄`에 걸친 값(`password = (` 다음 줄에 값) · `base64` 같은 것으로 감싼 값 · `4000자`가 넘는 한 줄 안의 값 · `목록에 없는 토큰 꼴`(SendGrid `SG.…`·npm·Slack 웹훅 주소 같은 것) · `get류가 아닌 함수`(`settings.value("db.password", "…")`)에 적힌 값.
  - `명령 줄·덤프에 적힌 값`: `-e 이름=값`·`--password=값`·`Authorization: Bearer …`·한 줄에 여러 `이름=값`·`"이름=값"` 목록 · Windows의 `set 이름=값` · Makefile의 `이름 ?= 값`·`이름 += 값` · `git diff`의 `-` 줄 가운데 이름 앞에 다른 글이 낀 것(`-export 이름=값`·`-# 이름: 값`·`-  - 이름: 값`)과 `@@ … @@` 뒤에 붙어 나온 줄·`줄번호:+이름=값` · 여러 이름에 한꺼번에 넣는 줄(`user, password = "u", "…"` — 앞 값만 가리고 뒤 값은 간다).
  - `틀 글로 보이는 주소 칸` — 주소의 `?token=` 칸 값이 `{{…`·`{…}`·`[x]…`·`$이름`·`${이름}`·`${{…` 꼴이거나 칸 이름에 `.`·`[`가 들면(`?user[password]=…`) 틀 글로 보고 둔다(`{`·`[`·`(`·`$`로 시작해도 이 꼴이 아니면 가린다 — `?token=$(cat 파일)`처럼 명령을 끼운 주소는 앞 낱말만 가려져 줄이 깨진다) · `세미콜론 뒤 주소 칸`(`;client_secret=…`처럼 `;` 뒤 칸은 이름이 `password`·`passwd`·`pwd`·`secret`·`token`·`api_key`·`apikey` 그대로일 때만 가린다) · `퍼센트로 감싼 주소`(주소 안에 `%3F…%3D`로 한 번 더 감싸 넣은 주소의 칸) · `타입을 적은 선언`(`password: str = "…"`·`const password: string = "…"`)의 값 · `백틱으로 감싼 값`(JS에서 따옴표 대신 백틱으로 감싼 글).
  - `결과를 바꿔 찍는 명령`(`base64`·`xxd` 같은 것)이 찍은 값.
  - `시험 파일`에서는 **이름으로 찾는 가림을 하지 않는다**(알려진 토큰 꼴·개인 키 덩어리는 시험 파일에서도 가린다) — `tests/` 같은 시험 폴더나 `test_*` 이름의 파일을 Read·Edit·Write로 열거나 Grep으로 그 폴더를 찾을 때, 그리고 줄 앞에 `시험파일:줄번호:`가 붙은 검색 결과 줄(명령으로 돌린 `grep -n`의 줄도)이다. 시험 파일에 진짜 값이 있으면 그대로 간다. 그 밖에 명령(Bash)으로 찍은 것은 시험 파일이어도 가린다 — 시험용 가짜 값을 봐야 하면 파일 읽기로 연다.
  - `띄어쓰기나 한글이 든 값`(라벨로 보고 둔다 — 띄어 쓴 암호문도 그대로 간다) · `이름이나 비밀 낱말과 같은 값`(`POSTGRES_PASSWORD=secret` 같은 것) · `값이 이름보다 앞선 XML`(`<property value="…" name="db.password"/>`) · `글 속에 한 번 더 감싼 JSON`(글 안에 `\"password\": \"…\"`로 적힌 것).
  - `@`로 가리킨 파일·따로 붙인 도구(MCP)의 결과 · 그림·PDF · Bash·Read·Grep·Edit·Write 밖의 도구(Windows의 PowerShell 도구·뒤에서 돌린 명령의 출력 읽기 같은 것)의 결과.
  - 같은 호출의 결과를 바꾸는 다른 훅이 있으면 어느 쪽 결과가 갈지 확인하지 못했다.
  - 가림이 **고장 나거나 10초 넘게 걸리면 원래 결과가 그대로 간다**(도구가 이미 돈 뒤라 닫을 길이 없다).
  - 사용자 화면·남는 대화 기록 파일이 가려지는지, 원격 기록 보내기(OpenTelemetry)를 켰을 때 그쪽에 원래 값이 가는지, 알림이 AI에게 닿는지는 확인하지 못했다.
  - 다른 길로 얻은 값을 AI가 답에 옮겨 적는 것.
- **잘못 가리는 것:** `본보기 값`(문서 속 `sk_test_…`·`changeme123` 같은 것)·`입력칸의 값`(`<input type="hidden" name="password" value="…">`처럼 이름이 비밀 낱말로 끝나는 입력칸에 적힌 값 — 숨긴 칸이 아니어도)·`공개 키`(`PUBLIC_KEY=…`)·`꺼내는 호출의 둘째 글`(`t.get("password", "…")`처럼 get류 호출의 둘째 칸에 적은 한 낱말 라벨 — `default="…"`으로 적은 것도)·`주소 속 넘김 토큰`(`?next_page_token=…`·`?csrf_token=…`처럼 비밀이 아니어도 이름이 `token`으로 끝나는 주소 칸)·`숫자 설정값`(`MAX_TOKEN = 4096`처럼 이름이 `token`으로 끝나는 숫자 설정값)·`주소 뒤 닫는 괄호`(마크다운 링크 `[글](주소#token=…)`에서 주소 뒤 `)`까지 가려진다)·`Go 코드 줄`(`token := 5`·`token := <-ch`처럼 이름이 비밀 낱말로 끝나는 변수에 따옴표 없이 넣는 줄)처럼 비밀이 아닌 값도 꼴이 맞으면 가린다 — AI는 그 값을 못 본다. 꼭 보여야 하면 **사용자가 그 값을 대화에 직접 적어 준다**. 끄는 길도 있지만 끄면 묻기·멈추기·거절·가림이 모든 프로젝트에서 다 꺼진다 — 다 쓰면 표시 파일을 지운다.
- Codex에는 이 확인도 가림도 없다(글 규칙만 남는다).
- devkit은 Claude Code의 거부 규칙·샌드박스를 건드리지 않는다. 쓰고 싶으면 그 도구의 설명서를 따른다.
- **끄는 법:** 사용자 폴더(`~` · Windows는 `C:\Users\<사용자 이름>`)에 `.devkit-guard-off`라는 빈 파일을 만든다. WSL에서는 WSL 안의 홈이다. 지울 때까지 묻기·멈추기·거절·가림이 **모든 프로젝트에서** 다 꺼지고, 꺼졌다고 따로 알리지 않는다. 끈 동안에는 규칙 한 장의 글만 남는다.

## 지우기

    python3 install.py --remove

지운 뒤에도 Claude Code가 받아 둔 사본 폴더(`plugins/cache/devkit`)는 남는다. 쓰이지 않으니 그대로 둬도 되고 손으로 지워도 된다.

## 여기서는 안 되는 것
| 자리 | 안 되는 것 | 대신할 방법 |
|---|---|---|
| Codex | 대화를 열 때 규칙 한 장이 실제로 읽히는지 **확인 못 함**(실제 Codex에서 본 적 없다) | 부탁 앞에 "AGENTS.md의 devkit 규칙을 지켜 줘"라고 한 줄 붙인다 |
| Codex | 큰 일 안내(start)·살펴보기(find)를 못 읽음 | 한 장대로 한다 |
| Windows | 대화를 열 때 규칙 한 장이 저절로 들어가는지 **확인 못 함**(훅이 `python`이라는 이름으로 도는지 Windows에서 본 적 없다) | 부탁 앞에 "devkit 폴더의 rules.md를 읽고 시작해 줘"라고 한 줄 붙인다 |
| Windows | 비밀값 파일 한 번 더 거르기(가림 포함): 이 확인은 돌려 보지 못했다 — 안 돌 수 있다 | 규칙 한 장의 글을 따른다 |
| 큰 프로젝트 | 살펴보기를 한 대화가 차례로 읽는다 — 값이나 시간이 모자라면 길 안내가 덜 찬다 | 길 안내의 "못 본 것"을 보고, 그 폴더만 다시 살펴 달라고 한다 |
| Python 3.8 | 3.8 문법으로 짰는지 글자 검사만 했고 실제 3.8로는 **돌려 보지 못함**(이 PC에는 3.10뿐) | 3.8에서 오류가 나면 더 새 Python을 쓰거나 알려 준다 |

Python 3, 그리고 Claude Code나 Codex.
