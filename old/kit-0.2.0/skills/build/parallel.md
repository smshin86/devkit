# 동시에 만들기 — `copies.py` 순서와 맡기는 글

`copies.py`는 이 스킬 폴더에서 두 칸 위의 `scripts/`에 있다. 사본은 프로젝트 폴더 밖(임시 자리)에 생기고(맨 `git add`·`git commit`으로 모으면 사용자가 따로 올려 둔 것까지 한 커밋에 삼켜서, 스크립트는 임시 색인을 쓴다), 사용자의 가지·하던 고침·커밋 안 한 파일은 건드리지 않는다. 끝 번호가 2(차례로 하라)면 `message`를 그대로 적고 차례로 한다.

## 하기 전에
`copies.py list <프로젝트>`를 먼저 돌린다.
- 남은 회차가 이 기록의 `만든 방법`에 적힌 것이면 내 것이다. 아래 "합치기와 되돌려 놓기"의 남은 걸음부터 잇는다.
- 기록에 적힌 회차가 `list`에 없으면 이미 얹고 치운 것이다. 얹혔는지 `copies.py since`로 보고 5번 걸음(맞춰 보기)부터 잇는다.
- 아니면 `made`를 쉬운 말로 보여 주며 한 번 묻는다: "<때>에 만든 임시 사본이 남아 있습니다. 다른 창에서 지금 만드는 중이 아니면 치우겠습니다." 만든 지 하루가 안 됐으면 권하는 답은 "두고 차례로 한다", 넘었으면 "치운다".
- `clean`은 늘 회차를 줘서 부른다. 물을 사람이 없으면 치우지 않고 차례로 한다.

## 사본 열기
`copies.py start <프로젝트> <조각 수>` → `copies` 목록의 `path`가 조각마다 일할 곳이다. 2번이면 차례로 한다.
**0번이면 손을 부르기 전에 바로** `## 조각`의 그 조각들 `만든 방법`을 `동시에(사본 <id>)`로 적는다. 대화가 끊겨도 다음 대화가 이 회차를 내 것으로 알아보고 이어 간다. 적어 두지 않으면 남의 것으로 보고 손들이 한 일을 버린다.
도구에 사본 기능이 따로 있어도 지금 상태에서 시작할 때만 쓴다. 커밋된 곳에서 시작하면 사용자가 하던 고침이 빠진다.

## 맡길 때 주는 글
아래 글을 조각마다 채워 **한 번에 모두** 보낸다(한 응답에 여럿 = 동시에). 대화 내용을 통째로 붙이지 않고 자리를 가리켜 준다. 두 조각이 같은 것(검색 조건, 같은 이름의 칸)에 닿으면 양쪽 `맞물림` 줄에 적는다. 앞서 한 시험에서 날짜 검색과 "지금 검색 그대로 엑셀 내려받기"가 따로 만들어져, 합쳐 놓고 보니 엑셀에서 날짜 조건이 빠져 있었다.
```
너는 조각 <P번호> 하나를 맡은 만드는 손이다.
- 일할 곳(사본): <path>. 여기서만 고친다. 커밋하지 않는다(모으는 것은 맡긴 쪽이 한다).
- git은 status·diff·log만 쓴다(stash·checkout·branch·reset·commit을 쓰지 않는다 — 사본은 본래 저장소와 가지를 같이 쓴다).
- 켜기·빌드·시험: <허락 줄 그대로>. "켜도 됨"이 아니면 돌리지 않고 읽어서 확인한 뒤 "돌리지 못함"으로 적는다.
- 읽기만 하는 곳(본래 폴더): <프로젝트 자리>. `.devkit/`과 git이 무시하는 설정·라이브러리는 사본에 없으니 여기서 읽는다. 찾을 것이 사본에 안 보이면 새로 만들기 전에 여기서 찾는다.
- 요청 원문: <요청 칸 그대로>
- 먼저 읽을 것: <본래 폴더>/.devkit/work/<기록 파일>의 장면·세 칸·닮은 것과 꺼낸 규칙. 작업 기록은 쓰지 않는다.
- 이 조각: <사용자에게 되는 일> → 확인: <S번호와 장면 글>. 닿아야 하는 곳: <목록>.
- 다른 조각: <P번호: 한 줄>… 그쪽 일은 하지 않는다. 맞물림: <같이 맞춰야 할 것 / 없음>.
- 하지 않는 것: 다른 손 부르기, 요청에 없는 것 넣기(떠오르면 보고의 "안 만들 것 후보"에).
- 결과가 달라지는 갈림길을 만나면 고르지 말고 멈춰 보고한다. 파일만 계속 읽는데 길이 안 보이거나 맡은 조각 밖의 구조를 바꿔야 할 것 같을 때도 억지로 하지 말고 "막힘"으로 보고한다. 사본에서 안 도는 검사는 "사본에서 못 돌림"으로 적는다.
- 보고(15줄 안): 상태(끝남 | 끝났지만 걸림 | 막힘 | 물을 것 있음) / 바꾼 파일과 곳마다 M·D 번호 / 돌린 검사와 결과 / 못 한 것 / 안 만들 것 후보.
```
- `<허락 줄>`은 `## 확인`에 적을 `- 허락:` 줄 그대로다(`../verify/run-ok.md`).
- 손이 또 다른 손을 부르게 하지 않는다. 합친 것을 보는 일은 맡긴 쪽과 검토 단계 몫이다.

## 보고 받기
보고의 말이 아니라 `git -C <사본> status --short`와 바뀐 파일을 직접 연다. 손은 같은 실수를 되풀이하고, 보고는 한 일이 아니라 했다고 믿는 것을 적는다.
- `끝남` → 바뀐 파일을 열어 M·D 번호에 맞는지 본다.
- `끝났지만 걸림` → 걸린 것을 합치기 전에 푼다.
- `물을 것 있음` → 답을 붙여 새 손에게 다시 맡긴다.
- `막힘` → 자료를 더 주거나, 조각을 쪼개거나, 더 센 손으로 바꾸거나, 그 조각만 본래 폴더에서 차례로 한다.
- 바꾼 것 없이 같은 손에게 같은 것을 다시 맡기지 않는다. 막혔다고 한 것은 무엇이든 달라져야 한다.

## 합치기와 되돌려 놓기
1. `copies.py merge <프로젝트> <회차>`. 끝 번호 0이면 바로 3번 걸음으로. `outside`가 비어 있지 않으면 손이 프로젝트 폴더 밖의 파일을 고친 것이다. 그 고침은 합쳐지지 않는다 — 옮기지 말고 사용자에게 어느 파일인지 알린다.
2. 끝 번호 3(부딪힘)이면 부딪힌 조각과 파일을 사용자에게 쉬운 말로 한 줄 알린다. 합쳐진 것은 `apply`로 얹고, 부딪힌 조각은 그 사본을 읽어 가며 본래 폴더에서 차례로 다시 만든다.
3. `copies.py apply <프로젝트> <회차>`. 끝 번호 4(만드는 동안 폴더가 바뀜)이면 멈추고 사용자에게 "만드는 동안 폴더가 바뀌었습니다"라고 알린다. **이때는 `clean`하지 않는다** — 합친 결과가 통합 사본(`int` 자리)에만 있다. `git -C <int 자리> diff --name-only devkit-tmp/<id>/snap`의 파일을 본래 폴더로 손으로 옮긴다. 겹치지 않는 파일은 그대로, `files`와 겹치는 파일은 양쪽을 읽고 합친다. 사용자 것을 지우지 않는다.
   끝 번호 6(얹을 수 없음)이면 **손으로 옮기지 않는다.** 본래 폴더에 같은 이름의 파일이 이미 있다는 뜻이고(`files`), 덮어쓰면 사용자 파일을 잃는다. `clean`하지 않고 멈춰서 사용자에게 그 파일을 알리고 어떻게 할지 묻는다.
4. 다 얹은 것을 그 파일 목록과 대조한 뒤에 `copies.py clean <프로젝트> <회차>` → `list`가 빈 것을 본다. 0번이면 바로 `clean <회차>`.
5. 합친 것 전체를 build `SKILL.md`의 "맞춰 본다"로 한 번 더 맞춰 본다. 합친 것의 검토는 검토 단계가 한다(`devkit:review`).

충돌 없이 합쳐졌다고 맞물린 것이 아니다. 각자는 다른 쪽이 무엇을 만드는지 모르고 만들었으니, 합친 것 전체를 요청 전부와 함께 만든 쪽이 아닌 눈에게 한 번 보인다. 조각마다 따로 본 것으로 끝내지 않는다.
