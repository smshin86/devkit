# 되돌려 적기 — 어디에, 어떤 꼴로, 어떻게 고치나

**언제 읽는가:** `SKILL.md` 1번에서 `.devkit/rules/`나 길 안내(`.devkit/guide.md`, 새 프로젝트는 맨 위 `AGENTS.md` — 찾는 차례는 `devkit:start`)를 고치기 직전.
새 꼴을 만들지 않는다. 줄 꼴·영역 파일 이름·`index.md`는 `../find/rules.md`를, 길 안내 제목은 `../find/first-guide.md`를 그대로 따른다. 길 안내가 아닌 `AGENTS.md`·`CLAUDE.md`(프로젝트가 AI에게 적어 둔 것)에는 적지 않는다.

## 적을 만한가
물음은 하나다 — **이 줄이 없으면 다음 사람이 같은 실수를 하거나 다시 한참 찾겠는가?**
- 아니면 적지 않는다. 지금 코드·시험·주석·`git log`로 다시 알 수 있는 것도 적지 않는다. 일을 했다는 사실이나 이번 이야기는 적지 않는다.
- 맞으면 **배운 것 하나에 줄 하나**. 여럿을 한 줄로 뭉치지 않는다.
- 다른 곳에 적힌 것(설계 글·기록·규칙 파일)은 되풀이하지 않고 자리만 가리킨다.

## 자리 가르기
| 배운 것의 성질 | 자리 | 예 |
|---|---|---|
| 찾기 어려웠던 것(어디에 있는지·어디서 이어지는지) | 길 안내(`.devkit/guide.md` 또는 맨 위 `AGENTS.md`) | 공통 내려받기 주소는 `/common/download.do`다 |
| 기계가 잡을 수 있는 것(고정된 글자 꼴·금지된 호출·파일 위치) | 프로젝트에 이미 있는 검사(시험·형식 검사·CI)가 있는데 안 돌고 있으면 보고에 알린다. **새 검사는 만들지 않는다.** | `.jsp` 닫는 태그 누락, 정해진 import 순서 |
| 판단이 드는 것(옆 코드와 맞는지·이 화면에 어울리는지) | `.devkit/rules/`의 그 영역 파일에 한 줄 | 목록 표는 `list_st1`을 쓴다 |
| 위 어디에도 안 맞고 다시 알 수 있는 것 | 적지 않는다 | |

## 줄 꼴 (`../find/rules.md` 그대로)
```
- <규칙 한 줄> — 예: `<경로>` · <n>/<m>곳 · 센 명령: `<명령>`
```
- 영역 파일 이름은 여섯뿐이다: `look.md` `behavior.md` `server.md` `query.md` `lock.md` `naming.md`. 다른 이름은 만들지 않는다.
- 파일이 없으면 만들고 첫 줄을 `# <영역 이름>`, 빈 줄, 규칙 줄로 한다. 파일을 만들거나 고치면 `index.md`의 한 줄 요약도 같이 고친다.
- 수는 손으로 세지 않고 검색 명령으로 세고, **그 명령을 줄 안에 남긴다**(명령 안에 백틱은 쓰지 않는다). `예:`의 경로는 프로젝트 뿌리 기준 하나, 줄 번호·별표 없이.
- 보기 (둘째는 JSP가 아니다):
```
- 첨부는 공통 내려받기 주소로만 내준다 — 예: `web/WEB-INF/jsp/bbs/view.jsp` · 14/14곳 · 센 명령: `grep -rl "common/download.do" web --include=*.jsp | wc -l`
- 목록 화면은 `components/DataTable.tsx`로 그린다 — 예: `src/pages/orders/List.tsx` · 12/14곳 · 센 명령: `grep -rl "DataTable" src/pages | wc -l`
```

## 같은 줄 찾기 (쓰기 전에)
1. `rules/index.md`의 한 줄 요약에서 닿는 파일을 고른다.
2. 그 파일에서 낱말로 검색한다: `grep -n "<낱말>" .devkit/rules/<파일>`.
3. 같은 말을 하는 줄이 있으면 **보태지 않고 고쳐 쓴다**(수·예·명령을 새로 센 것으로). `index.md` 요약이 달라졌으면 같이 고친다.
4. 없을 때만 새 줄을 쓴다.

## 규칙을 고치는 길은 넷뿐이다
1. 닮은 것이 규칙과 다르면 그 규칙을 검색 명령으로 다시 센다. 센 결과가 줄과 다르면 줄을 고친다.
2. `check.py`가 "없는 파일"을 찍으면 그 줄의 예를 지금 있는 파일로 바꾼다. 같은 방식을 하는 파일이 이제 없으면 다시 세어 보고 줄을 지운다.
3. 사용자가 "그건 틀렸다"고 하면 그 줄을 고친다. 사용자 말을 코드로 확인한 뒤 고친다.
4. 고칠 때는 줄을 쌓지 않고 고쳐 쓴다. 규칙 파일에는 지금 상태만 쓴다.

**이번에 만든 코드가 규칙과 다르다고 규칙을 코드에 맞추지 않는다.** 코드가 방식을 어긴 것일 수 있다. 그 판단은 검토의 `W` 줄과 사용자 몫이다.

## 지운다
- 읽고도 행동이 달라지지 않는 줄(누구나 아는 말·틀의 기본·한 파일의 사정)은 지운다.
- 적힌 파일이 없어진 줄은 낡은 줄이다 — 고치거나 지운다.

## 하지 않는다
- 비밀값(비밀번호·키·접속 계정·쿠키)은 규칙에도 길 안내에도 어디에도 적지 않는다. 값 대신 "어디에 있다"만 적는다.
- `.devkit/`에 새 문서 종류(결정 기록·학습 노트·점수 표)를 만들지 않는다.
