# 화면 생김새 규칙

## 언제 읽는가
화면을 새로 만들거나 화면 생김새를 바꿀 때, `.devkit/rules/look.md`가 없을 때.

## 이 파일이 하는 일
`.devkit/rules/look.md`가 이 프로젝트의 디자인 문서 노릇을 한다. 새 화면이 이웃 화면과 같은 얼굴이 되게 하는 기준이다. 뽑는 절차와 줄 모양은 `rules.md`를 따르고, 여기서는 화면 생김새에서 무엇을 뽑는지만 말한다.

## 뽑는 것
- 쓰는 공통 스타일 파일. 이웃 화면에 `lookup`을 돌려 "불러오는 파일"과 묶음 수(`126/154`)로 안다.
- 버튼·표·입력 칸·검색 칸·쪽 넘김에 붙이는 클래스 이름과 쓰는 곳 수. 수는 검색 명령으로 센다.
- 색과 간격은 스타일 파일에 실제로 있는 값만 옮긴다. 지어낸 값(예: 어디에도 없는 13px)은 적지 않는다. 길 안내 `## 스타일`의 값 줄(프로젝트에 `DESIGN.md`가 있으면 그것)에 이미 적힌 값은 여기 다시 적지 않고 그 줄을 가리킨다 — 같은 값을 두 곳에 적으면 한쪽만 고쳐져 어긋난다.
- 빈 목록·오류·권한 없음일 때 이웃 화면이 어떻게 보이는지(문구와 모양). 이웃이 하는 만큼만 적는다.
- 화면 틀(위쪽 메뉴·옆 메뉴)을 어느 묶음이 주는지는 서버 코드에서 확인해 적는다. 지도로는 알 수 없다.

## 새 화면에서 하지 않는 것
프로젝트 스타일에 없는 것을 넣으면 새 화면만 따로 논다. 프로젝트 스타일에 있으면 그대로 따른다.
- 프로젝트에 없는 색(보라색 그라데이션 같은 것)을 쓰지 않는다. 프로젝트의 실제 색만 쓴다.
- 큰 둥근 모서리, 무거운 그림자, 카드가 격자로 깔리는 배치를 프로젝트에 없는데 넣지 않는다.
- 지어낸 안내문과 설명 문구를 넣지 않는다. 이웃 화면에 있는 문구만 쓴다.
- 색만으로 상태를 알리지 않는다. 글자나 모양도 같이 쓴다(이웃 화면이 이미 하는 방식이 있으면 그것).
- 간격은 스타일 파일의 눈금에서 고른다. 눈금에 없는 값을 새로 만들지 않는다.

## 줄 모양 보기
`.devkit/rules/look.md`에 들어가는 줄의 보기다(수는 지어낸 보기다). 줄 모양은 `rules.md`의 것과 같다.
```
- 목록 표는 `list_st1` 클래스를 쓴다 — 예: `web/WEB-INF/jsp/bbs/list.jsp` · 73/80곳 · 센 명령: `grep -rl "list_st1" web --include=*.jsp | wc -l`
- 검색 칸의 버튼은 `btn_search` 클래스를 쓴다 — 예: `web/WEB-INF/jsp/notice/list.jsp` · 40/52곳 · 센 명령: `grep -rl "btn_search" web --include=*.jsp | wc -l`
- 버튼은 `Button`의 `variant`(`primary`·`secondary`)로 고른다 — 예: `src/pages/orders/List.tsx` · 12/14곳 · 센 명령: `grep -rl "<Button" src/pages | wc -l`
```

## 확인
바꾼 화면이 같은 묶음 이웃과 같은 스타일 파일을 불러오는지 `lookup`으로 본다. 새 화면과 이웃 화면 둘에 `lookup`을 돌려 "불러오는 파일"을 맞춰 본다. 다르면 이유가 있는지(이웃도 일부만 불러오는지) 확인하고, 이유가 없으면 이웃 쪽으로 맞춘다.
