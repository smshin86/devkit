# 방식 뽑기와 틀린 규칙 바로잡기

## 언제 읽는가
이번 일이 닿는 영역이 `.devkit/rules/`에 없을 때, 닮은 것이 적어 둔 규칙과 다를 때, 사용자가 규칙이 틀렸다고 할 때, `first-guide.md`의 "나눠 살피기"로 맡은 영역을 뽑을 때.

## 영역 여섯
파일 이름은 고정이다. 다른 이름은 만들지 않는다. 뽑은 영역만 파일이 있다(없는 파일은 아직 안 뽑은 것이다).

| 파일 | 영역 |
|---|---|
| `look.md` | 화면 생김새 (뽑는 법은 `find`의 `look.md`가 따로 안내한다) |
| `behavior.md` | 화면 동작 |
| `server.md` | 서버 처리 |
| `query.md` | DB 질의 |
| `lock.md` | 잠금 (누가 여는지 보는 법) |
| `naming.md` | 이름 짓기 |

## 뽑는 법
이번 일이 닿는 영역 하나씩만 뽑는다 — `first-guide.md`의 "나눠 살피기"일 때만 여섯을 다 뽑고(프로젝트에 없는 영역은 건너뛴다), 그때도 영역마다 아래 대표 5~10장만 읽는다. 수천 장짜리 프로젝트를 한 번에 읽으면 끝이 안 난다.
- 대표 5~10장을 고른다: 서로 다른 폴더에서 하나씩, 가장 최근에 고친 것, `lookup`에서 가장 많이 끼워진 것. 한 폴더에서만 고르면 그 폴더 방식이 프로젝트 방식처럼 보인다.
- 적는 것은 여러 곳에서 되풀이되고, 처음 온 사람이 짐작하지 못하는 것뿐이다. 언어·틀의 기본(예: 반복은 틀이 주는 반복 문법으로 돈다)은 안 적는다. 한두 곳뿐이면 규칙이 아니라 그 파일의 사정이다.
- 규칙을 먼저 쓰고 "~를 쓴다"로 못 박는다. 까닭 설명과 지난 이야기는 안 쓴다. 한 줄에 규칙 하나다.
- 한 개념에 한 줄이다. 같은 개념의 줄이 이미 있으면 새로 쓰지 않고 그 줄을 고친다.
- 사람에게 왜 그렇게 했는지 묻지 않는다. 코드가 보여 주는 것만 적는다.
- 영역 파일의 첫 줄은 `# <영역 이름>`, 빈 줄, 그다음은 규칙 줄만 둔다.
- 영역 파일을 만들거나 고치면 `index.md`도 같이 고친다.

## 세는 법
- 수는 늘 검색 명령으로 센다. 손으로 세지 않는다(앞 실측에서 손으로 센 수가 두 번 틀렸다).
- `n/m곳`의 `m`은 같은 종류 전부다(목록 화면 규칙이면 목록 화면 전부). `m`도 검색 명령으로 구한다. `n`이 `m`보다 크면 잘못 센 것이니 둘 다 다시 센다.
- 센 명령을 줄에 남긴다. 명령 없는 수는 소문이다. 명령 안에는 백틱을 쓰지 않는다(줄이 깨진다).
- `예:`의 파일은 그 방식을 실제로 하는 파일이고, 센 명령의 결과에 나오는 것이다.
- 명령은 프로젝트 뿌리에서 그대로 돌리면 같은 수가 나와야 한다.

## 줄 모양
```
- <규칙 한 줄> — 예: `<경로>` · <n>/<m>곳 · 센 명령: `<명령>`
```
- 경로는 프로젝트 뿌리 기준 `/` 경로 하나다. 줄 번호와 별표(`*`)는 쓰지 않는다. 규칙 글 안에는 ` — 예: `를 쓰지 않는다.
- 보기 (둘째는 JSP가 아니다):
```
- 목록 표는 `list_st1` 클래스를 쓴다 — 예: `web/WEB-INF/jsp/bbs/list.jsp` · 73/80곳 · 센 명령: `grep -rl "list_st1" web --include=*.jsp | wc -l`
- 목록 화면은 `components/DataTable.tsx`로 그린다 — 예: `src/pages/orders/List.tsx` · 12/14곳 · 센 명령: `grep -rl "DataTable" src/pages | wc -l`
```

## 틀린 규칙을 바로잡는 길
뽑은 규칙은 틀릴 수 있다. 틀린 규칙을 따르면 프로젝트 방식과 어긋난 화면이 하나 더 생긴다.
1. 수를 다시 셀 때도 검색 명령으로 센다.
2. 닮은 것이 규칙과 다르면 그 규칙을 다시 센다. 센 결과가 규칙 줄의 수와 다르면 줄을 고친다.
3. 점검 스크립트가 `예:`의 파일이 아직 있는지 본다. 없다고 나오면 새 예를 찾아 줄을 고친다.
4. 사용자가 "그건 틀렸다"고 하면 그 줄을 고친다. 변명하지 않고, 사용자 말을 코드로 확인한 뒤 고친다.
5. 고칠 때는 줄을 보태지 않고 고쳐 쓴다. 지우지 않고 쌓으면 읽을 수 없게 된다(앞 실측: 쌓아서 675KB가 됐다).
- 규칙 파일에는 지금 상태만 쓴다. 언제 바뀌었는지의 이야기는 적지 않는다.
- 고친 영역이 `index.md`의 요약과 달라졌으면 요약도 고친다.

## index.md
`.devkit/rules/index.md`는 파일마다 한 줄 요약이다. `find`가 이 요약만 보고 이번 일에 닿는 파일을 고른다.
```
# 규칙 목록

- `look.md` — 목록·입력 화면의 공통 스타일 이름과 쓰는 곳
- `lock.md` — 화면과 내려받기를 잠그는 방법
```
- 위 보기대로 파일 이름은 백틱으로 감싸고 ` — ` 뒤에 요약을 쓴다. 파일 이름은 영역 여섯 중 하나다.
- 요약은 "무슨 일을 하면 이 파일을 열어야 하는가"가 드러나게 쓴다.
