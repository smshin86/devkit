# 켜서 써 볼 때 — 놓치기 쉬운 것과 검사 돌리는 법

켜기 전에 `run-ok.md`대로 허락이 `켜도 됨`인지 본다. 아니면 이 글을 쓰지 않고 `reading.md`로 간다.

## 켜기 전에
- 이미 켜져 있는 것은 그대로 쓰고 끄지 않는다.
- 내가 켠 명령과 번호(pid)를 적어 둔다. 나중에 `끈 것:` 줄에 쓴다.
- 켜고 누르는 도구를 찾으려고 디스크 전체를 뒤지거나(`find /`) 다른 프로젝트 폴더의 것을 빌려 쓰지 않는다. 이 프로젝트 폴더와 이미 깔려 있는 명령에 없으면 아래 "화면 누르는 도구가 없을 때"로 간다.
- 바꾼 것이 시작 쪽(서버 시작 파일·DB 설정·테이블 만들기·처음 자료)이면 처음부터 켜서 첫 화면까지 본다. 앞 장면이 안 되면 그 뒤 장면으로 넘어가지 않는다.
- 시작 쪽을 바꿨는데 이미 켜져 있던 것이 바꾸기 전의 모습이면, 그것으로 본 것은 `됨`이 아니다(켜 둔 채로는 새 시작을 못 봤다). 새로 켤 수 없으면 `확인 못 함`과 까닭을 적는다.

## 장면마다 볼 것
화면이 바뀐 것만 보고 끝내지 않는다.
- 저장했으면 다시 열어서 저장된 것을 본다. 받아들여졌다는 것만으로는 모른다. 저장하는 꼴이나 읽어 들이는 길을 고쳤으면 장면에 없어도, 이미 저장된 것이 있는 채로 다시 열어 그대로 보이는지 본다.
- 화면 뒤 요청의 상태를 본다. 4xx는 보낸 쪽(주소·값·로그인)이 틀린 것이고, 5xx는 서버 안이 깨진 것이라 나눠서 적는다. 눌렀는데 요청이 아예 나가지 않았으면 그것도 적는다(버튼이 서버에 이어지지 않은 것).
- 화면 콘솔에 새 오류가 생겼는지 본다. 이미 있던 경고까지 고치려 하지 않는다.
- 장면에 빈 목록이나 잘못 넣은 값이 있으면 그 화면도 본다.
- 본 것 칸에는 부른 주소·누른 것과 나온 것을 적는다. 예: `/board/list?from=2026-11-01&to=2026-11-10 → 3건, 모두 기간 안`.

## 화면 누르는 도구가 없을 때
- 주소를 직접 부른다. 폼이 보내는 이름 그대로 값을 담고, 로그인이 필요하면 받은 쿠키를 이어서 쓴다.
- 이 길로는 화면 스크립트·스타일이 돌지 않는다. 본 것 칸에 "화면 스크립트는 못 봄"을 쓰고, `reading.md`의 화면 쪽 이음매(`screenmap.py lookup`/`used-by`)와 "다시 열 때"로 보탠다.

## 시험 자료
알아볼 이름으로 넣는다(예: "devkit 시험 글 1"). 넣은 것은 `## 확인`에 적어 사용자가 지울 수 있게 한다.

## 검사 돌리기
- 프로젝트가 적어 둔 명령(README·빌드 파일·CI)만 돌린다. 명령을 지어내지 않는다.
- 고치는 동안은 관련 검사 하나, 마지막 고침 뒤 전체 검사를 한 번 돌린다. 코드를 안 바꾸고 같은 검사를 다시 돌리지 않는다.
- 통과로 적으려면 그 검사가 실제로 돌았다는 숫자가 있어야 한다. 0개를 돌렸거나 끝 번호를 못 봤으면 통과가 아니다. 글자 모양만 보는 검사가 지났다고 빌드가 된 것은 아니다.
- 실패를 "원래 있던 것"이라고 쓰려면 근거가 있어야 한다: 바꾸기 전의 결과, 또는 이번에 바꾼 것과 닿지 않음을 코드로 보인 것. 근거가 없으면 이번 고장이다.
- 바깥 서비스나 비밀값이 없어 못 돌리면 흉내 내지 말고 `확인 못 함`과 까닭을 적는다.
- 검사 결과는 `돌린 검사:` 줄에 명령과 숫자로 적는다.

## 끝낼 때
내가 켠 것만 켤 때 적어 둔 번호로 끈다. 이름으로 한꺼번에 끄지 않는다(`devkit:start`의 "절대 안 한다"). 꺼졌는지 확인하고 `끈 것:` 줄에 적는다. 눈으로만 알 수 있는 것(글자 모양·흐름이 자연스러운지)은 `못 본 것:` 줄에 적는다. 결과 칸은 `됨` `안 됨` `읽어서는 이어짐` `확인 못 함` 넷뿐이다.
