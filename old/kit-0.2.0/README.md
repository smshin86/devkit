# devkit

이미 있는 프로젝트에서 AI에게 무엇을 만들어 달라고 할 때, **요청한 것만, 그 프로젝트의 방식대로** 만들고
실제로 써 보며 확인하도록 돕는 스킬 묶음이다. Claude Code와 Codex에서 쓴다.

## 깔기
이 폴더에서 한 번 친다. 그 뒤 새 대화를 연다.

    python3 install.py

(Windows에서 `python3`이 없다고 나오면 `python install.py`.)
명령을 치는 것이 낯설면, 이 폴더에서 Claude Code나 Codex를 열고 "install.py를 실행해 줘"라고 해도 된다.
컴퓨터에 있는 쪽(Claude Code, Codex)에 깔린다. 다시 치면 새 판으로 바뀐다.
깐 뒤에 이 폴더를 옮기거나 지우면 다시 깔아야 한다.

**Codex에서는 처음 한 번 "믿는다"를 눌러야 한다.** 깐 뒤 Codex를 처음 열면 이 묶음을 믿을지 묻는다.
묶음이 바뀌어 다시 깔면 또 묻는다.

## 쓰는 법
따로 부를 필요 없다. 평소처럼 "이 화면에 무엇을 넣어 주세요"라고 부탁하면 된다.
AI가 일의 크기(작은 고침 / 기능 하나 / 큰 일)를 먼저 말해 주고, 크기에 맞는 단계만 밟는다.
평범한 기능 하나는 받기·찾기·만들기까지 하고 결과를 적어 닫는 짧은 길로 간다. 로그인·권한·파일 첨부·개인정보·돈에 닿거나,
큰 일이거나, "꼼꼼히" 해 달라고 하면 여섯 단계를 다 지나는 긴 길로 간다. 어느 길인지도 처음에 한 줄로 말해 준다.
틀렸으면 그 자리에서 말하면 바꾼다. 질문은 한 번에 하나이고, 늘 권하는 답이 붙는다.
고칠 것 없이 "이 프로젝트가 어떻게 짜였는지 알려 주세요"라고 하면, 코드는 건드리지 않고 무엇으로 만들었는지·어디에 무엇이 있는지·조심할 곳을 길 안내(프로젝트 모양을 적어 두는 글)에 적고 쉬운 말로 알려 준다.

| 스킬 | 하는 일 |
|---|---|
| `start` | 문. 일의 크기를 정하고(살펴만 달라는 부탁은 크기 없이 길 안내와 규칙만 쓴다), 어느 단계에서나 지킬 것(요청한 것만, 본 것만 "됨")을 잡는다 |
| `intake` | 받기. 부탁을 "이럴 때 이렇게 된다" 장면과 "만들 것 / 정해야 하는 것 / 안 만들 것"으로 적어 보여 준다 |
| `find` | 찾기. 이미 있는 가장 닮은 것을 찾아 화면부터 자료 저장소까지 따라가고, 따를 방식을 꺼낸다 |
| `build` | 만들기. 일을 조각으로 나눠 차례로, 또는 서로 기다릴 필요 없으면 동시에 만든다 |
| `verify` | 확인. 장면마다 직접 써 보고 `됨` `안 됨` `읽어서는 이어짐` `확인 못 함` 중 하나로 적는다 |
| `review` | 검토. 만든 쪽이 아닌 눈이 "요청대로인가"와 "이 프로젝트 방식대로인가"를 따로 보고, 보안을 훑는다 |
| `wrap-up` | 마무리. 배운 것을 남기고, 쉬운 말로 보고하고, 작업 기록을 닫는다 |

## `.devkit` 폴더
기능 하나 이상의 일을 하거나 프로젝트를 살펴 달라고 하면 프로젝트 안에 `.devkit` 폴더가 생긴다. 하던 일의 기록과 찾은 규칙을 두는
AI의 작업 메모다. git 프로젝트에서는 이 PC에서만 통하는 제외 목록에 들어가 올라가지 않는다.
SVN 프로젝트에서는 올릴 때 목록에 보일 수 있다 — `.devkit` 폴더는 제 작업 메모입니다. 올릴 때 목록에 보여도 체크하지 마세요.
대화가 끊겨도 다음 대화가 이 기록을 보고 이어 간다.
새 프로젝트를 처음부터 만들면 길 안내(폴더 모양·켜는 법을 적은 글)는 `.devkit` 대신 프로젝트 맨 위 `AGENTS.md`에 쓰고, 옆에 `@AGENTS.md` 한 줄짜리 `CLAUDE.md`를 둔다(그 자리에 이미 두신 파일이 있으면 건드리지 않고 `.devkit` 안에 쓴다).
이 둘은 제외 목록에 들지 않는다 — 다른 AI 도구도 스스로 읽게 하려는 것이다. 이미 있는 프로젝트의 `AGENTS.md`·`CLAUDE.md`는 읽기만 하고 고치지 않는다(devkit이 새 프로젝트에 쓴 `AGENTS.md`는 그 뒤의 일에서도 고쳐 쓴다).

## Codex 안내 줄
Codex가 devkit을 스스로 꺼내 쓰지 않으면 이 명령으로 `~/.codex/AGENTS.md`에 안내 세 줄을 넣는다.

    python3 install.py --codex-note

이미 있으면 다시 넣지 않는다. 지울 때(`--remove`) 같이 지워지고, 사용자가 쓴 다른 줄은 건드리지 않는다.

## 지우기

    python3 install.py --remove

지운 뒤에도 Claude Code·Codex가 받아 둔 사본 폴더(`plugins/cache/devkit`)는 남는다. 쓰이지 않으니 그대로 둬도 되고 손으로 지워도 된다.

## 여기서는 안 되는 것
| 자리 | 안 되는 것 | 대신할 방법 |
|---|---|---|
| Codex | 대화를 열 때 devkit 안내가 저절로 들어가는지 **확인 못 함**(실제 Codex에서 본 적 없다) | 안 들어가면 `--codex-note`를 쓰거나, 부탁 앞에 "devkit:start를 읽고 시작해 줘"라고 한 줄 붙인다 |
| Windows | 대화를 열 때 devkit 안내가 저절로 들어가는지 **확인 못 함**(Windows에서 본 적 없다. `python3`이라는 이름이 없을 수 있다) | 같은 한 줄을 부탁 앞에 붙인다. 스킬 자체는 안내 없이도 부르면 읽힌다 |
| Python 3.8 | 3.8 문법으로 짰는지 글자 검사만 했고 실제 3.8로는 **돌려 보지 못함**(이 PC에는 3.10뿐) | 3.8에서 오류가 나면 더 새 Python을 쓰거나 알려 준다 |
| 화면을 누르는 도구가 없을 때 | 화면을 직접 눌러 보지 못하니 결과가 `됨`이 아니라 `읽어서는 이어짐`까지만 나온다 | 사람이 한 번 눌러 보고 말해 준다 |
| 배포 | 서버에 올리기·배포는 하지 않는다 | 따로 한다 |
| 화면 시안 | 화면을 어떻게 그릴지 시안을 만드는 일은 하지 않는다 | 디자인 도구나 사람이 정한 시안을 준다 |
| 속도 점검 | 느린 곳을 재고 고치는 일은 하지 않는다 | 따로 요청한다 |
| 자료 저장 구조(DB) | 저장 구조를 바꾸는 일은 하지 않는다. 이미 들어 있는 자료를 바꾸거나 지우기 전에는 먼저 묻는다 | 구조를 바꾸는 일은 사람이 하거나 따로 요청한다 |

## 필요한 것
Python 3, 그리고 Claude Code나 Codex.
저작권과 가져온 곳은 `CREDITS.md`에 있다.
