# devkit — 얇은 길잡이가 도구를 골라 부르고(지휘), doctor가 그 목록을 돌본다

표시: **[사용자]** 사용자가 말한 것 · **[관측]** 이번에 돌리거나 파일로 본 것 · **[문서]** 남의 글에서 읽은 것(돌려 보지 않음) · **[제안]** 내가 정한 것(사용자가 고칠 수 있다) · **[확인 필요]** 만드는 동안 한 번 확인해야 닫히는 것 · **[물음]** 사용자만 답할 수 있는 것.

## 0. 앞 문서와의 관계 — 그대로 두는 것과 뒤집는 것

**그대로 둔다.** 꾸러미 0.9.1의 바닥: 한 장의 세 가지와 문(큰 일 가르기) · 스킬 셋(`start` · `find` · `check`) · 훅이 걸린 사건 넷과 그 판정(세션 시작 · 비밀값 거르기 · 가리기 · 끝내기 전 점검) · 작업 기록(`.devkit/work/`). `start`의 「크기와 지날 단계는 devkit이, 누구를 부를지는 effort-router 표가」 줄도 그대로다.

**뒤집거나 고친다.** 앞 설계(2026-11-19)의 줄 번호로 적는다. 까닭은 1절.

| 앞 설계의 줄 | 새 꼴 |
|---|---|
| 28줄 「여러 도구를 깔아 조합하지 않는다」 | 일의 종류마다 더 잘하는 남의 도구를 **골라 부른다**. 한 일에 차례를 정하는 쪽은 하나다(4.2절). |
| 282줄 「다른 도구를 안에 넣어 돌리기」를 하지 않는다 | 남의 도구를 **안에 싣지는 않는다**(복사 없음 · 라이선스 그대로). 깔려 있으면 부르고, 없으면 설치를 알리고 devkit 혼자 한다. 따로 깔아야 하는 프로그램이 생긴다. |
| 27줄 · 7-5 「AI 도구 어느 것에도 묶이지 않는다」 | 한 장 · 스킬 셋은 그대로 묶이지 않는다. **지휘와 doctor는 Claude Code에서만** 돈다(플러그인 기록 · 훅에 기댄다). |
| 203줄 「사용자의 전역 설정은 건드리지 않는다」 | devkit은 전역 `CLAUDE.md` · `settings.json`의 **글을 직접 고치지 않는다**. 다만 doctor가 승인받아 플러그인을 깔거나 마켓을 등록하면 Claude Code가 `settings.json`의 `enabledPlugins` · `extraKnownMarketplaces`에 적는다 **[관측 · 문서]** — 승인 화면에 그 사실을 같이 보인다. |
| 294줄 「`rules.md`를 고치면 한 장의 측정은 다시」 | 한 장에 **한 줄을 보탠다**(4.2절). 측정은 다시 하지 않는다(8절 — 실제 일 셋으로 본다). 재어 둔 값은 「그 줄이 없던 한 장」의 것으로 남는다(약점). |
| 291줄 「폴더 하나에서만 켠다. PC 전체는 따로 허락」 | **그대로 둔다 [사용자: 프로젝트마다 켠다]** — 「전역 업데이트」는 devkit이 켜진 곳들의 판을 맞춘다는 뜻으로 읽는다. PC 전체로 켜는 것은 사용자가 말한 때만(`install.py --scope user`). |
| 「커밋 · 푸시는 말할 때만」(한 장과 `start`) | 일하는 대화에서는 그대로다. **묻지 않는 예외는 하나** — doctor가 devkit 저장소의 도구 목록 파일 하나를, 사실 칸만 고쳐 커밋 · 푸시하는 것(6.3절 · 스위치가 켜진 저장소에서만). |

## 1. 무엇을 왜

**[사용자]** 「얇은 절차로 가되, 각 단계별 어떤 도구들을 가져다 사용하는게 좋을지가 잡혀있으면 좋을꺼 같은데, 없으면 설치하게 하고」 · 「현재 gh에 존재하는 영역 별 도구들」 · 「상황에 맞춰서 더 잘하는 부분들이 있잖아? 그걸 적재적소에 진행하게 하는거지」 · 「devkit 자체가 메인 에이전트로써 진두지휘」 · 「내pc가 포멧이 되어 모든게 초기화 됐을때도 생각을 해줘야 돼~ 현재 환경만 보지말고 신규 환경에서도!」 · 「devkit:docter 를 실행하면 해당 git에 들어가 업데이트 된 부분이 있다고 하면 패치해주고 devkit에 대한 최적화를 진행해주는 부분까지 … 전역 업데이트 및 git push까지」.

**까닭.** 0.9.1까지의 devkit은 「혼자 다 하는 얇은 한 장」이었다. 재어 보니 한 장은 일을 망치지 않지만, 요구 묻기 · 버그 재현 · 계획 쓰기처럼 남의 도구가 이미 더 깊게 해 둔 자리에서는 보탤 것이 없었다. 그래서 devkit의 몫을 바꾼다 — **무엇을 할지 다 적는 글**에서 **지금 일이 어떤 일인지 가르고, 그 일을 잘하는 도구를 불러 주고, 끝을 지키는 길잡이**로.

**목표**
1. 대화가 열리면 devkit이 「상황 → 도구」 표를 싣고, 메인 대화가 그 표대로 도구를 **스스로** 부른다(사용자가 도구 이름을 외우지 않는다).
2. 도구가 없거나 깨져도 일은 된다 — 한 번 알리고 한 장대로 한다.
3. 포맷한 새 PC에서 저장소 하나를 받아 두 걸음(깔기 → doctor)이면 같은 상태가 된다.
4. `devkit:doctor` 한 번으로 진단 · 갱신 · 반영이 끝난다. 바꾸는 일은 한 화면에 모아 **한 번** 묻는다.

**하지 않는 것**
- 남의 도구의 글 · 코드를 꾸러미에 복사해 싣기. 스크립트를 내려받아 바로 실행하는 식의 설치.
- 대화가 열릴 때마다 망에 나가 최신을 확인하기(갱신은 doctor를 부른 때만).
- 재기 차례를 새로 만들기(8절). Codex 쪽 지휘.
- 써 보지 않은 도구를 표에 올리기(후보 목록에만 둔다 · 4.3절).

**되면 안 되는 것(돌아가도 실패로 본다)**
- 작은 일에 도구가 불려 느려지고 비싸지는 것.
- 한 일에 절차 도구 둘이 같이 붙어 서로의 차례를 덮는 것.
- 도구가 없거나 깨졌다는 까닭으로 일이 멈추는 것.
- doctor가 사용자의 다른 커밋을 같이 밀어 올리거나, 묻지 않고 규칙 글 · 훅 코드를 바꾸는 것(원격에서 **당겨 와서** 바뀌는 것 포함).
- devkit이 켜진 범위가 사용자 모르게 넓어지는 것(사람 없이 도는 다른 대화에 훅이 들어간다).
- **`Read`로 따라 읽는 남의 절차(pstack)**가 사용자 모르게 바뀐 채 지시로 들어오는 것.

**못 막는 길(그대로 적어 둔다)**
- 공식 마켓의 도구(superpowers · 맷포콕)는 Claude Code가 **스스로 올린다**(자동 갱신이 기본으로 켜져 있다 **[문서]** · 같은 날 다른 플러그인이 배경에서 바뀐 것을 봤다 **[관측]**). `Skill`로 부르는 글과 그 플러그인 자신의 세션 시작 훅은 devkit이 막지 못한다. 막으려면 사용자가 그 마켓의 자동 갱신을 끈다 — doctor는 그 길을 알려 주기만 한다.
- 지휘는 글로 하는 지시다. 훅처럼 반드시 걸리지는 않는다 — 반드시 걸려야 하는 것(끝내기 전 점검 · 비밀값)은 지금처럼 훅이 맡는다.

## 2. 지금까지 본 것

**이 PC에 깔린 것 [관측 · 2026-11-26]**
- `devkit@devkit` — 기록은 **범위 local · 옛 시험 폴더 하나 · 판 0.2.0**이고, 깔린 자리는 2026-11-18에 **베껴 둔 옛 사본**이다(스킬 이름부터 지금과 다르다). 저장소는 0.9.1이다. 다른 폴더(이 저장소 포함)에서는 devkit이 켜져 있지 않다. 마켓 등록은 폴더 꼴이고 저장소의 `kit/`를 가리킨다.
- `kit/install.py`는 범위를 말하지 않고 깐다 — Claude Code의 기본 범위는 **user(PC 전체)**다. 그리고 그 지우기 명령은 기본 범위가 user라 지금의 local 기록을 지우지 못한다.
- `superpowers` 7.0.2 · `mattpocock-skills` 1.3.1(둘 다 공식 마켓 · user 범위) · effort-router(플러그인이 아니라 `~/.claude/skills/effort-router/` + `~/.claude/agents/*.md` + 전역 `CLAUDE.md`의 단편 · 출처 주소는 그 폴더의 설치 메모에 있다).
- 「깔림」과 「켜짐」은 다르다 — 깔린 기록이 남아 있는데 꺼 둔 플러그인이 실제로 있다.
- pstack은 이 PC에 **깔려 있지 않다**(시험은 빈 설정 폴더에서만 했다).

**버릴 시험 [관측 · 2026-11-26 · 0.55달러 · 실행마다 한 번 · 모델은 sonnet]**
- 세션 시작 훅이 `hookSpecificOutput.additionalContext`로 실은 글은 `-p` 실행에서도 맥락에 들어온다(훅을 건 실행 둘). 이 실행들에는 devkit도 superpowers도 읽히지 않아 **세션 시작 훅이 하나뿐**이었다. 훅은 환경 변수로 바꿔 끼운 기록 파일을 읽었다 — 진짜 설정 폴더의 기록을 찾는 길은 돌지 않았다.
- 다른 실행 하나(훅 없음 · 설정 출처를 프로젝트로만 좁힘)에서 연습 폴더의 `CLAUDE.md`가 따라지지 않은 것으로 보였다. 까닭은 모른다 — 그래서 「프로젝트 규칙 파일은 `-p`에서 안 실린다」고 말할 수는 없다.
- pstack 0.15.48(MIT)은 Skill 도구로는 59개 가운데 58개가 잠겨 있다. 절차 파일 셋을 차례로 **Read해 따르게** 하면 따른다 — 「버그」 줄로 가름 → 파일 셋 읽음 → 재현 → 실패하는 시험 먼저 → 고침 → 숨긴 확인 0건(0.139달러). pstack이 없을 때는 설치 명령을 알리고 직접 고쳐 숨긴 확인 0건(0.074달러).
- 빈 설정 폴더에서 `claude plugin marketplace add cursor/plugins` → `claude plugin install pstack@cursor-plugins`가 된다.

**약점 — 이 글이 기대는 것이 얼마나 얇은지**
- 각 한 번 · sonnet 하나다. 표가 없던 판도 같은 버그를 절반 값에 고쳤다 — **pstack을 부르는 쪽이 더 낫다는 증거는 없다.** 본 것은 「부르라고 하면 부른다」뿐이다.
- 「상황표는 훅이 싣는다」의 근거는 「훅 하나의 글이 실린다」까지다. 훅 둘이 같이 실리는 것은 남의 문서로만 읽었다 **[문서]**.
- 미확인: superpowers · effort-router가 두 줄로 물러나는지 · pstack의 위임 일꾼 길 · 계획 쓰기 스킬이 계획 파일에서 멈추는지.
- 남의 도구가 파일 이름을 바꾸면 그 줄은 깨진다. pstack 절차는 토큰을 많이 쓴다.

**GitHub의 영역별 도구 [문서 · 2026-11-25 · 별 수 · 갱신 · 라이선스 · 설치법만 봄]** — `docs/2026-11-18-도구-조사.md`와 그 뒤 조사. 써 본 것은 넷뿐이라 **첫 판의 표에는 그 넷만** 올린다(4.3절에 후보).

## 3. 접근

| | 꼴 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| 가 | 안내 표만 — 「이 일엔 이 도구」를 글로 알려 주고 사용자가 부른다 | 가장 얇다 · 깨질 것이 없다 | **[사용자]**가 원한 「진두지휘」가 아니다. 도구 이름을 외워야 한다 |
| 나 | 남의 도구의 좋은 부분을 꾸러미에 옮겨 싣는다 | 설치가 한 번 · 위쪽이 바뀌어도 안 깨짐 | 라이선스 · 낡음 · 한 장이 다시 두꺼워짐 |

**고른 것: 다.** **[사용자]**가 방향(「진두지휘」)과 doctor의 꼴(나눠 푸시)을 승인했다. 지휘자는 **메인 대화**다 — 일꾼(서브에이전트)은 다른 일꾼을 부르지 못하므로, devkit을 「지휘하는 에이전트」로 따로 띄우지 않고 메인 대화가 읽는 글로 싣는다.

## 4. 지휘 — 상황표와 도구 목록

### 4.1 흐름

1. 대화가 열린다 → 세션 시작 훅이 ⓐ 한 장(지금 그대로) ⓑ **상황표**를 싣는다. 이때 망에 나가지 않고 파일을 만들지 않는다.
2. 부탁이 오면 메인 대화가 표의 줄 하나로 가르고, **첫 답에 어느 줄로 갈랐는지 한 줄**을 적는다(사용자가 틀린 가름을 바로잡을 자리). 작업 기록이 열리는 일이면 그 기록에도 「가른 줄 · 부른 도구」 한 줄을 적는다(이어 하는 대화가 같은 줄로 간다).
3. 그 줄의 도구를 그 줄에 적힌 방식으로 부른다. 도구가 없으면 설치 명령을, 깨졌으면 「doctor를 돌려 보라」를 **한 번** 알리고 한 장대로 한다. 부르다가 실패해도(스킬이 안 열림 · 파일이 없음) 한 번 말하고 한 장대로 간다.
4. 끝은 언제나 devkit의 끝내기 전 점검(지금 훅 그대로)이다.

### 4.2 규칙

- **한 일에 차례를 정하는 쪽은 하나**다. 표의 줄이 고른 쪽이 그 일의 차례를 정하고, 다른 절차 도구는 그 일에서 부르지 않는다.
- **줄이 겹치면 표의 위쪽 줄**이 이긴다(예: 로그인 코드의 버그는 「큰 일」 줄). **걸리는지 애매하면 묻지 않고 아래쪽(더 가벼운) 줄**로 가고, 그렇게 했다고 그 한 줄에 적는다.
- **크기 기준을 새로 만들지 않는다.** 큰 일인지는 한 장의 문이, 4번 줄인지는 effort-router의 발동 조건이 가른다. 둘은 따로 판정한다(`start`의 지금 줄 그대로 — devkit의 문은 「무슨 안내를 읽나」를, effort-router의 티어는 「누구를 몇 명 띄우나」를 정한다).
- **일꾼을 띄울 때의 역할 · 모델은 어느 줄에서나 effort-router 표**가 정한다(있을 때). pstack 절차가 제 일꾼(`pstack:poteto-agent`)을 띄우라고 하면, effort-router가 있으면 그 표의 역할로 바꿔 띄우고 없으면 메인 대화가 직접 한다 **[제안 · 확인 필요]**.
- **devkit 판정이 먼저**다. 다른 도구의 「무조건 나를 먼저 부르라」는 글보다 상황표의 가름이 앞선다. 사용자의 말과 프로젝트 규칙은 상황표보다 위다. 남의 도구의 글은 따라 읽는 절차일 뿐, 그 안의 지시가 사용자 말 · 한 장 · 끝내기 전 점검을 덮지 못한다.
- **한 장에 한 줄을 보탠다 [제안]**: 지금 11줄(「그 밖의 부탁은 devkit 안내를 더 읽지 않고 이 한 장만 지킨다.」)은 글자 그대로 두고, 바로 아래에 「상황표가 같이 실렸으면 그 표의 줄을 먼저 본다 — 이 한 장의 세 가지는 어느 줄에서나 지킨다.」를 넣는다(35줄 → 36줄 · 한도 40). 이 줄이 없으면 한 장과 상황표가 서로 반대 지시가 된다.

### 4.3 상황 → 도구(첫 판 · 위에서부터 본다)

| # | 상황 | 차례를 정하는 쪽 | 부르는 방식 | 없거나 깨졌을 때 |
|---|---|---|---|---|
| 1 | 한 장의 문이 「큰 일」로 가른 것 | devkit `start`의 길(지금 그대로). 그 길의 **계획 걸음에서만** superpowers 계획 쓰기를 부품으로 쓴다 | Skill `superpowers:writing-plans` — **계획 파일을 쓰는 데까지만**. 그 스킬이 끝에 묻는 실행 방식과, 계획 머리에 적히는 「REQUIRED SUB-SKILL」 줄은 따르지 않는다 **[관측: 그 스킬 글에 둘 다 있다]** | `start`의 길 그대로 |
| 2 | **재현이 필요한** 버그 · 성능 · 화면 똑같이 맞추기 · 밤새 돌리기 · PR 머지까지 돌보기 | pstack의 해당 절차 | 절차 파일을 차례로 **Read**해 따른다(Skill로는 잠겨 있다) | 한 장 + `check` |
| 3 | 무엇을 만들지 갈리는 부탁(요구가 흐릿하다) | 맷포콕 `grilling` — 답이 모이면 이 표를 다시 본다 | Skill. 용어가 걸리면 이어서 `domain-modeling`(`grill-with-docs`는 모델이 부를 수 없게 잠겨 있다 **[관측]**) | `start`의 「묻는 법」 |
| 4 | 한 장의 문에는 안 걸리지만 effort-router의 발동 조건에 걸리는 기능 추가 · 리팩터링(「중간 크기 기능」) | effort-router의 티어 차례(계획 → 검토 → 구현 → 리뷰) | 그 표의 역할 일꾼을 띄운다 | 한 장 + `check` |
| 5 | 그 밖 — 작은 일(원인이 보이는 버그 고치기 포함) | devkit 한 장 | 도구를 부르지 않는다 | — |

- 어느 줄에서나: 기존 코드 살피기와 화면 표는 `find`, 끝은 `check`와 끝내기 전 점검 훅.
- 2번 줄은 값이 든다(한 번 본 것: 같은 버그에 약 두 배). 그래서 「재현이 필요한」으로 좁혔다.
- effort-router에서는 **티어 판정과 역할표만** 쓴다. 작업 서술을 바깥 서비스로 보내는 판단 계층 · 브라우저 실행 계층은 상황표에서 부르지 않는다. 그 본체 글(약 120KB)은 4번 줄에 걸렸을 때만, 티어 판정과 역할 배정 절만 읽게 절 이름을 상황표에 박는다. 그 글이 스스로 권하는 다른 계층을 메인 대화가 따르는 것은 글로만 막는다(못 막는 길).
- 시험 · 검토 · 배포 걸음에는 첫 판에 따로 붙는 도구가 없다 — `check`와 effort-router의 리뷰 역할이 맡는다. 후보가 써 본 뒤 올라올 자리다.

**후보 목록(표에 올리지 않는다 — 실제 일에 한 번 써 본 뒤 사용자가 올린다)** **[문서]**: 화면 디자인(impeccable) · 코드 검토(open-code-review) · 보안(security-audit-skill · trailofbits/skills) · 코드 지도(Understand-Anything · graphify) · 진행 기록(planning-with-files · beads) · 있는 것 다시 쓰기(ponytail) · 배포(미정). 올리지 않기로 한 것: 갱신이 끊긴 것 · 라이선스가 걸리는 것(AGPL · 자체 라이선스) · 스크립트를 내려받아 바로 돌리는 설치.

### 4.4 도구 목록 파일 — `kit/tools.json` **[제안]**

도구에 대한 **사실**은 파일 하나에 모은다(파이썬 기본 모듈로 읽히는 JSON). **PC마다 다른 상태는 이 파일에 넣지 않는다** — 「이 PC에서 지금 쓸 수 있나」는 훅이 대화가 열릴 때마다 스스로 본다(4.5절). 그래서 한 PC의 고장이 다른 PC의 멀쩡한 도구를 끄지 않는다.

| 칸 | 뜻 | doctor가 묻지 않고 고칠 수 있나 |
|---|---|---|
| `id` · `repo` · `license` | 도구 이름 · 저장소(`소유자/이름`) · 라이선스 | 아니오(글) |
| `plugin` | 깔린 것을 찾는 열쇠(`pstack@cursor-plugins` 꼴) — 플러그인이 아니면 비움 | 아니오 |
| `install` | 설치 명령 줄들(플러그인 한 줄 꼴만) — 손 설치면 `hand`와 안내 주소 | 아니오 |
| `call` | 부르는 방식: `skill` · `read` · `agent` | 아니오 |
| `probe` | 「쓸 수 있다」의 증거 — 깔린 자리 아래 이 파일들이 있어야 한다. `skill` 도구는 그 스킬 글이 잠기지 않았는지도 본다 | 아니오 |
| `read` · `read_sha256` | `read` 도구가 따라 읽기 시작하는 파일들과 그 내용의 지문 | 아니오(승인) |
| `use` | 표에서 쓸지(사용자가 내려 두면 `false`) | 아니오 |
| `checked_version` · `checked_commit` · `checked_on` | 확인한 판 · 깔린 기록의 커밋 · 날짜 | **`skill` · `agent` 도구만 예.** `read` 도구는 승인(6.2절) |

- 상황표의 **문장**은 따로 `kit/conduct.md`에 둔다(한도 30줄 · 실린 글이 훅 하나의 상한 10,000자 안 **[문서]**). 문장은 규칙 글이므로 doctor가 묻지 않고 고치지 못한다.
- effort-router는 라이선스 글과 플러그인 선언이 없다 **[관측]** → `install`은 `hand`(저장소 주소와 그쪽 설치 글을 알림), `probe`는 `~/.claude` 아래 스킬 글과 역할 파일. devkit이 대신 깔지 않는다. 남에게 줄 때는 이 줄이 「없음」으로 내려가도 나머지가 돈다.

### 4.5 싣는 꼴 — 세션 시작 훅을 하나 더 건다 **[제안]**

- `session_start.py`(한 장을 바이트 그대로 찍음)는 **고치지 않는다**. 새 스크립트 `kit/scripts/conduct.py`를 같은 사건에 **둘째 훅**으로 건다(지금 훅 줄과 같은 꼴 · `commandWindows` 줄 포함). 한 훅이 죽어도 다른 훅(한 장)은 실린다. 훅 선언을 못박은 시험(`test_hooks_json`)은 세션 시작 훅을 하나로 못박고 있어 **기대 값을 고쳐야 한다**(7절).
- `conduct.py`가 지키는 것(지금 훅들과 같은 바닥): 기본 모듈만 · 어떤 경우에도 조용히 0으로 끝남 · 파일과 폴더를 만들지 않음 · 망에 나가지 않음 · 사용자 설정 폴더는 **읽기만** 하고 그 내용을 찍지 않음.
- 도구를 **「있음」으로 싣는 조건(다 참일 때만)**:
  1. 깔린 기록이 있고 그 범위가 지금 폴더에 닿는다(user이거나, project · local이면 그 기록의 프로젝트 자리가 지금 프로젝트다).
  2. 꺼져 있지 않다(user · project · local 설정의 켬 목록을 읽기만 한다).
  3. 깔린 자리가 플러그인 보관 폴더 아래의 실제 폴더이고 `probe` 파일이 다 있다.
  4. `read` 도구면 깔린 기록의 커밋이 `checked_commit`과 같고 따라 읽는 파일의 지문이 `read_sha256`과 같다(기록에 커밋이 없으면 지문만).
  5. `use`가 `false`가 아니다.
- 갈래마다 싣는 글: **있음**(자리와 부르는 방식) · **없음**(설치 명령과 「그동안은 한 장대로」) · **깨짐**(깔렸는데 1~3이 어긋남 → 「doctor를 돌려 보세요 · 그동안은 한 장대로」) · **확인한 판과 다름**(4가 어긋남 → 같은 말). 뒤의 셋은 모두 한 장대로 돈다.
- 실어 주는 자리 글은 `[A-Za-z0-9._@/+-]`만 · 200자 안일 때만 싣고, 홈 폴더는 `~`로 줄여 적는다(남이 정한 이름이 지시처럼 실리거나, 사용자 이름이 저장소 문서로 옮겨 가지 않게).
- 상황표를 실을 수 없으면(목록 파일이 깨짐 등) **아무것도 싣지 않는다** — 그러면 대화는 0.9.1과 같이 돈다.
- **[확인 필요]** 세션 시작 훅 둘의 글이 둘 다 실리는지(문서로는 그렇다) · 진짜 설정 폴더의 기록을 찾는 길 · 대화형 대화에서도 같은지.

### 4.6 superpowers · effort-router를 물러나게 하는 자리

- superpowers는 **지우지 않는다**. 그 플러그인이 대화 첫머리에 싣는 「스킬이 있으면 반드시 먼저 부르라」와 devkit의 가름이 부딪히는 자리는, 그 글 스스로의 「사용자 지시가 스킬보다 먼저」에 기대어 **두 줄**로 푼다 **[제안]**: ① 이 프로젝트에서 어느 도구를 부를지는 devkit 상황표가 정한다 ② effort-router는 상황표가 부를 때만 돈다(**[사용자]** 「호출시 진행」).
- **넣는 자리는 프로젝트 맨 위의 `CLAUDE.local.md`** **[제안]** — 나만 읽는 파일이라 팀 저장소에 딸려 올라가지 않는다. 프로젝트 맨 위는 git 맨 위 폴더(git이 아니면 doctor를 부른 폴더)다. 파일이 없으면 만들고, git 프로젝트면 이 PC의 제외 목록에 한 줄을 더한다(`.devkit/`에 하던 것과 같은 법).
- **넣고 빼는 것은 doctor**가 한다(그 프로젝트에서 부른 때 · 승인 화면에 두 줄 원문과 「effort-router의 늘 발동을 이 프로젝트에서 멈춥니다」를 보인다). 두 줄은 `<!-- devkit:begin -->` · `<!-- devkit:end -->` 사이에 넣는다. 뺄 때는 줄 끝을 고르게 한 뒤 **지난 판들이 넣던 본문의 지문 목록 가운데 하나와 같을 때만** 지운다(문구가 바뀐 뒤에도 옛 줄이 빠진다) — 손댄 흔적이 있으면 건드리지 않고 알린다.
- 승인이 없으면 넣지 않고, 상황표의 「devkit 판정이 먼저」 한 줄만으로 간다.
- 그래도 superpowers가 끼어들면 사용자가 그 프로젝트에서만 끌 수 있다 — doctor가 명령을 **알려 주기만** 한다: `claude plugin disable superpowers@claude-plugins-official --scope local`(`project` 범위는 함께 쓰는 사람에게도 간다 **[문서]**).
- **[확인 필요]** `CLAUDE.local.md`의 두 줄로 실제로 물러나는지. effort-router의 전역 글은 「프로젝트의 `CLAUDE.md` · `AGENTS.md`가 우선」이라고만 적혀 있어 `CLAUDE.local.md`가 거기에 드는지는 돌려 봐야 안다. 안 되면 이 절은 「안 됨」으로 적고, ⓐ 끄기 명령 안내 ⓑ 사용자가 전역 글의 발동 문장을 직접 고칠 안(보여 주기만)만 남긴다.

### 4.7 도구가 남기는 문서를 잇기(맨 뒤 · 따로 승인)

- 문서는 **도구가 쓰던 자리**에 그대로 둔다(계획 · 설계 글, 용어집, 결정 기록, 과업 폴더). devkit이 옮기거나 다시 쓰지 않는다. 어느 폴더를 「도구의 문서 자리」로 볼지는 도구 목록의 줄에 둔다.
- 하려는 일: 열린 작업 기록이 있을 때 그 기록에 `문서: <경로>` 한 줄이 이어지고, 끝내기 전 점검이 이어지지 않은 문서를 짚는다(막지는 않는다).
- 훅 자리는 이 부품을 만들 때 정한다. 후보는 둘이다 — 파일이 써질 때 도는 **새 스크립트**(있는 기록 파일에 한 줄 덧붙이기만 하고 만들지는 않는다) / 끝내기 전 점검이 한꺼번에 본다. 어느 쪽이든 비밀값 훅 둘은 고치지 않는다.
- 못 잡는 것: 셸 명령으로 쓴 문서(백로그 001과 같은 틈) · 작업 기록이 없는 작은 일의 문서.

## 5. 새 PC — 포맷 뒤의 길

1. Claude Code · git · python3 · GitHub CLI(`gh`)를 깔고 둘 다 로그인한다(이 저장소는 `gh`로 인증해 받고 민다).
2. devkit 저장소를 받는다 → **켤 프로젝트 폴더에서** `python3 <devkit 저장소>/kit/install.py`를 돌린다. `install.py`는 범위를 받는다 — **기본은 `local`(그 프로젝트 · 나만)**이고, `--scope user`(PC 전체)는 사용자가 말한 때만 쓴다 **[사용자: 프로젝트마다 켠다]**. 켤 프로젝트마다 한 번씩 돌린다. 끝에 한 줄로 알린다: 「새 대화에서 `devkit:doctor`를 한 번 돌리면 도구를 맞춥니다」.
3. 새 대화에서 `devkit:doctor`: 도구 목록과 이 PC를 견주어 없는 것을 보인다. 플러그인 한 줄로 깔리는 것은 **승인 한 번**에 깐다. 손 설치(effort-router)는 저장소 주소와 그쪽 설치 글을 알린다(전역 `CLAUDE.md`의 단편도 그쪽 설치 글이 다룬다 — devkit은 대신 하지 않는다).
4. 이 저장소의 주인이면 한 줄을 다시 켠다: `git config --local devkit.autopush true`.

- doctor를 돌리기 전에도 대화는 된다 — 상황표의 줄이 「없음 → 한 장대로」로 실릴 뿐이다.
- doctor의 모양 검사는 `doctor.py` 안에 기본 모듈로 둔다. pytest는 꾸러미를 **고치는** 사람만 깐다(새 PC의 걸음에 넣지 않는다).
- **지금 이 PC의 첫걸음**: 깔린 옛 사본(0.2.0)에는 doctor가 없다 → 2번을 손으로 한 번 돌린다. 옛 시험 폴더의 local 기록은 그 폴더에서 `claude plugin uninstall devkit@devkit --scope local`로 지운다(doctor가 명령을 알려 준다).
- 도구 목록이 저장소에 있으므로 「무엇을 어느 판으로 확인하고 썼는지」가 포맷 뒤에도 남는다. **이 설계 글 · 백로그 · 도구 조사는 지금 저장소에 올라가 있지 않다**(이 PC의 제외 목록에 `docs/superpowers/` · `docs/*.md`가 있다 **[관측]**) — 포맷하면 사라진다. 이 세 글은 훑은 뒤 올린다(10절 답 2).
- **[확인 필요 · 모델 없이]** superpowers · 맷포콕을 빈 설정에 까는 길 · 폴더 마켓의 플러그인이 지금 판에서 **그 자리에서 읽히는지 베껴지는지**(문서는 「그 자리」, 이 PC의 옛 기록은 「베낌」이다) · 프로젝트 설정의 끔이 user 범위 설치를 그 프로젝트에서 끄는지.

## 6. `devkit:doctor`

꼴: 얇은 스킬 글(`kit/skills/doctor/SKILL.md`) + 읽고 세는 스크립트(`kit/scripts/doctor.py`). 사용자가 부른 때에만 돈다. 진단 → **할 일 한 화면 · 승인 한 번** → 실행 → 한 일과 안 한 일 보고.

### 6.0 되돌리기 어려운 일과 승인

| 일 | 승인 |
|---|---|
| 도구 목록의 사실 칸 커밋 하나를 `main`에 푸시 | 저장소마다 스위치를 켠 것이 승인이다 — 그 뒤로는 묻지 않는다 **[사용자가 승인한 꼴]** |
| devkit 저장소 당기기 — 도구 목록의 사실 칸만 바뀐 경우 | 묻지 않는다 |
| devkit 저장소 당기기 — 그 밖(`kit/`의 글 · 훅 코드 등)이 바뀐 경우 | 바뀐 파일 목록을 보이고(훅 코드는 따로 짚는다) 승인 |
| 깔린 플러그인 올리기 · 공식이 아닌 마켓 새로 받기 | 도구 · 판 → 판 · 범위 · 그 도구의 훅이 바뀌는지를 보이고 승인 |
| 새 도구 깔기 | 명령 원문 · 범위 · 그 도구가 거는 훅 · 마켓이 등록으로 남는다는 것 · Claude Code가 설정 파일에 적는 열쇠를 보이고 승인 |
| 따라 읽는 도구(pstack)의 새 커밋을 「확인함」으로 적기 | 바뀐 파일 수 · 따라 읽는 파일의 바뀐 줄 수 · `hooks/` 변경 여부를 보이고 승인 |
| `CLAUDE.local.md` 두 줄 넣기 · 빼기 | 프로젝트마다 승인 |
| 규칙 · 스킬 · 훅 · 상황표 문장 고치기(「최적화」 안) | 고칠 안과 잰 근거를 보이고 승인 |
| devkit을 켜는 범위 바꾸기 | doctor는 **하지 않는다** — 지금 범위를 지킨다(바꾸는 것은 사용자가 `install.py`로) |

승인이 필요한 줄은 한 화면에 모아 **한 번** 묻고, 사용자가 줄마다 뺄 수 있다. 전부 자동으로 하는 스위치(`--all`)는 이번에 만들지 않는다.

### 6.1 진단(파일 읽기 · devkit 원격 받아 오기만)

- devkit 자신: `doctor.py`가 돌고 있는 자리가 저장소의 `kit/`인가 베낀 사본인가 · 어느 범위 · 어느 프로젝트에 켜져 있나 · 깔린 판 대 저장소 판 · 저장소가 원격보다 뒤졌나(`GIT_TERMINAL_PROMPT=0 git fetch` — 저장소의 원격 가지 기록만 바뀐다 · 합치지 않는다).
- 도구마다: 깔렸나 · 켜졌나 · 범위 · 깔린 판과 커밋 · 확인한 커밋(목록) · `probe` · 따라 읽는 파일의 지문 · 잠김 여부. 「마켓이 지금 주는 판」은 여기서 보지 않는다(마켓 새로 받기는 쓰기라서 6.2의 승인 줄이다).
- 저장소 자리는 마켓 등록 글(`known_marketplaces.json`의 devkit 줄)에서 찾는다. git 저장소가 아니거나 원격이 없으면 git 걸음을 건너뛰고 그렇다고 말한다.
- 잰 것(「최적화」의 재료 — 잴 수 있는 것만): 상황표 길이(줄 · 글자) · 세션 시작 훅 둘의 시간(세 번 가운데 값) · 죽은 줄(목록에는 있는데 상황표가 안 쓰는 도구와 그 반대 · `probe`가 없는 줄 · 확인 날짜가 90일 넘은 줄) · 판 어긋남.
- 망에는 devkit 원격과(6.2에서) 도구의 마켓 이름만 나간다. 사용자 · 프로젝트 이름은 안 나간다.

### 6.2 갱신

- **devkit 저장소 당기기.** 다 참일 때만 본다: 가지가 `main`(`git symbolic-ref -q --short HEAD`) · 윗줄 가지가 있다 · 작업 폴더가 깨끗하다(`git status --porcelain`이 빔) · 원격보다 앞선 커밋이 없다. 뒤진 만큼의 바뀐 파일(`git diff --name-only HEAD..@{u}`)이 `kit/tools.json` 하나이고 칸으로 견줘 `checked_*`만 바뀌었으면 묻지 않고 앞으로만 당긴다(`git merge --ff-only`). 그 밖이면 6.0의 승인 줄이다. 조건이 안 맞으면 손대지 않고 까닭을 말한다.
- **도구 올리기**(승인 뒤): 마켓은 **이름을 붙여** 그것만 새로 받고(`claude plugin marketplace update <이름>` — 이름이 없으면 전부 받는다 **[관측]**), 도구는 깔린 범위 그대로 올린다(`claude plugin update <도구> --scope <범위>`). 판이 같으면 아무 일도 안 일어날 수 있다 **[문서]** — 그대로 「달라진 것 없음」으로 적는다. 공식 마켓 도구는 doctor가 올리지 않아도 이미 올라와 있을 수 있다 — 본 대로 적는다.
- **올린 뒤(또는 저절로 올라와 있던 것)의 기록**:
  - `skill` · `agent` 도구: `probe`가 다 있고 잠기지 않았으면 `checked_*`를 깔린 기록의 판 · 커밋 · 오늘로 적는다(묻지 않는다).
  - `read` 도구: 깔린 커밋이 `checked_commit`과 다르면 6.0의 승인 줄이다. 승인되면 `checked_*`와 `read_sha256`을 새로 적는다. 승인 전에는 목록을 고치지 않는다 — 훅이 스스로 「확인한 판과 다름」으로 내려 싣는다.
  - `probe`가 깨졌으면: 「깨짐」으로 보고한다. 목록은 고치지 않는다(훅이 스스로 내려 싣는다).
- doctor는 내려받은 스크립트를 돌리지 않는다. 도구의 설정 명령(예: pstack의 설정 스킬)도 돌리지 않는다.

### 6.3 반영

**ⓐ 묻지 않고 하는 것 — `kit/tools.json`의 `checked_*`(`skill` · `agent` 도구 것)만.**
1. 고치기 전에 본다: 사용자가 그 파일에 손댄 것이 없다(`git diff --quiet HEAD -- kit/tools.json`) · 가지가 `main` · 원격을 받아 온 뒤 **뒤지지도 갈라지지도 않았다**. 하나라도 아니면 파일을 고치지 않고 화면에만 보인다. **스위치가 꺼진 저장소(남이 받은 사본)에서도 파일을 고치지 않는다** — 화면에만 보인다(다음 당기기가 막히지 않게).
2. 고친 뒤 `doctor.py`의 모양 검사를 통과하고, HEAD의 것과 **칸으로 견줘** `checked_*` 밖이 바뀌었으면 되돌리고 멈춘다.
3. **그 파일 하나만** 담아 커밋한다(`git commit --only -- kit/tools.json` · 정해진 글머리). 커밋 뒤 `git show --name-only HEAD`로 한 파일인지 본다.
4. 푸시는 다 참일 때만: 스위치가 켜져 있다(`git config --local --type=bool --get devkit.autopush`가 `true` — 값이 없으면 꺼짐) · `HEAD..@{u}`가 0 · `@{u}..HEAD`가 1 · `HEAD~1`이 `@{u}`다(사용자의 다른 커밋을 같이 밀지 않는다) · 억지로 밀지 않는다. 아니면 커밋만 남기고 까닭을 말한다.

**ⓑ 승인받고 하는 것 — 글과 코드.** 한 장 · 스킬 글 · 훅 스크립트 · 상황표 문장 · 목록의 글 칸(`install` · `call` · `probe` · `read` · `license` · `use` · 새 도구 줄) · `read` 도구의 `checked_*`와 지문. doctor는 **고칠 안과 잰 근거**를 보여 주고 멈춘다. 승인되면 그 안대로 고치고, 시험을 돌리고(pytest가 있을 때), 판 번호를 올릴지 묻고, 커밋 · 푸시도 그 승인 안에서 한다. 「최적화」는 6.1에서 잰 것이 한도를 넘거나 죽은 줄이 있을 때의 고칠 안으로만 나온다 — 감으로 글을 다듬지 않는다.

**ⓒ 깔린 devkit 맞추기 — 「전역 업데이트」.**
- 깔린 것이 저장소의 `kit/`를 **그 자리에서** 읽으면: 당긴 것이 곧 갱신이다. 다시 깔지 않고 「새 대화부터 적용됩니다」만 말한다. (그래서 당기기의 승인이 곧 훅 코드의 승인이다. 그리고 이 꼴에서는 **저장소 작업 폴더에서 고친 것이 커밋 전에도 다음 대화부터 살아 있는 훅**이 된다 — README에 적는다.)
- **베낀 사본**이면: `kit/`가 깨끗할 때만, **지우지 않고** 깔린 범위 그대로 올린다(`claude plugin update devkit@devkit --scope <기록의 범위>`). 올린 뒤 깔린 기록에 devkit이 그대로 있는지 본다 — 없으면 보고의 **첫 줄**에 「devkit이 빠졌습니다 — 비밀값 거르기와 끝내기 전 점검이 꺼져 있습니다」와 되살리는 명령을 적는다.
- 어느 쪽이든 doctor는 켜는 범위를 바꾸지 않는다.

## 8. 무엇으로 됐다고 보나 · 하지 않는 것 · 나중에

- **됐다고 보는 기준 [사용자와 정한 것]**: 재기 차례를 새로 만들지 않는다. 사용자가 실제 프로젝트에서 일 셋 — 작은 일 하나(5번 줄) · 재현이 필요한 버그 하나(2번 줄) · 중간 크기 기능 하나(4번 줄) — 을 맡겼을 때 ① 첫 답에 어느 줄로 갈랐는지가 나오고 ② 그 줄의 도구가 실제로 불리고(작은 일에서는 안 불리고) ③ 끝내기 전 점검이 돈다. 좋다 · 나쁘다의 판단은 사용자가 한다.
- **보류**: 재는 도구 · 백로그 여덟 건(001~008) · 1.0의 선. 이 판에서 손대지 않는다.
- **나중에**: 문서 잇기(7번) · 후보 도구 올리기 · `--all` · Codex 쪽 지휘 · 남에게 줄 때의 꼴(effort-router 줄 빼기 · 스위치 설명) · 「부르는 쪽이 정말 더 나은가」를 재는 일.

## 9. 제약

- 꾸러미의 스크립트는 파이썬 3.8 · 기본 모듈만. 훅은 10초 안(목표는 훨씬 짧게) · 조용히 0.
- 대화가 열릴 때의 훅은 망 · 쓰기 · 설치를 하지 않는다. 바꾸는 일은 전부 doctor 안이고, doctor는 사용자가 부른다.
- devkit은 사용자의 전역 `CLAUDE.md` · `settings.json`의 글을 직접 고치지 않는다(0절의 단서 그대로). 프로젝트에는 승인받은 `CLAUDE.local.md` 두 줄만.
- 다른 도구를 이 PC에 실제로 까는 것은 그때마다 승인받는다. 이 설계가 승인돼도 그것이 설치 승인은 아니다.
- 꾸러미 글에 연습 무대의 일감 · 숨긴 기준을 옮기지 않는다. 시험 글에 진짜처럼 생긴 비밀값 · 계정 · 홈 폴더 이름을 적지 않는다.
- 만드는 동안의 확인(**[확인 필요]**)은 버릴 폴더 · 빈 설정 · 가짜 홈에서만 한다. 모델을 돌리는 것은 셋이다 — 훅 둘이 다 실리는지 · 두 줄로 물러나는지 · 계획 쓰기가 계획 파일에서 멈추는지. 나머지는 모델 없이 본다. 돈은 10절의 한도 안에서 쓴다.

## 10. 만드는 이에게 맡기는 것 · 내가 정한 것 · 사용자가 정할 것

**맡기는 것**: `tools.json`의 정확한 열쇠 이름과 중첩 · `conduct.md`의 줄 꼴과 훅이 붙이는 문장 · `doctor.py`의 하위 명령 나누기 · 커밋 글머리 · 시험 파일 나누기 · README 문장. 다만 4.5의 바닥과 「있음」 조건 다섯, 6.0의 표, 6.3ⓐ의 조건은 글자 그대로 지킨다.

**내가 정한 것(틀리면 고쳐 주세요)**
1. 상황표는 새 훅 스크립트로 따로 싣는다 — 한 장 훅은 그대로 두고, 훅 선언 시험의 기대 값은 고친다.
2. 사실은 `tools.json`, 문장은 `conduct.md`. **PC마다 다른 상태는 파일에 두지 않고 훅이 매번 스스로 본다.**
3. 묻지 않는 것은 「도구 목록의 사실 칸 커밋 · 푸시」 하나로 좁혔다. **당겨 온 꾸러미 변경 · 플러그인 올리기 · 따라 읽는 도구의 새 판 받아들이기는 한 화면에 모아 한 번 승인**받는다(승인된 「갱신은 자동」보다 좁다 — 원격에서 바뀐 훅 코드가 묻지 않고 이 PC에서 도는 길을 막으려는 것).
4. 한 장에 한 줄을 보태고, 측정은 다시 하지 않는다(약점으로 적어 둠).
5. 물러나게 하는 두 줄은 프로젝트의 `CLAUDE.local.md`에(프로젝트마다 승인) — 팀 저장소에 안 올라가게.
6. 「중간 크기 기능」은 effort-router의 차례에 맡기고, 큰 일은 지금처럼 `start`의 길 + effort-router 병행 그대로 둔다.
7. doctor는 devkit이 켜진 범위를 바꾸지 않는다. 다시 깔 때 지우고 깔지 않는다.
8. 문서 잇기(7번)는 이 판에서 빼고, 써 본 뒤 따로 승인받는다.

**[물음]의 답(2026-11-26 · 사용자 「권하는 방향으로 진행하자」)**
